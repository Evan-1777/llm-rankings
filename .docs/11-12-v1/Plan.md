## 1. 背景与目标

维度增多后榜单列宽失控；评分侧无法表达「该维度对某模型不适用」。本轮四件事：

| # | 需求 | 目标形态 |
|---|------|----------|
| 1 | 维度组 | 任意选取若干维度给同一组名即成组；成组只是捆绑展示，组内维度不因成组损失任何功能 |
| 2 | 导出榜单图片 | 榜单页小尺寸按钮一键导出 PNG |
| 3 | 未评分置顶 | 评分台与评分弹窗中未评分项排在最前 |
| 4 | 跳过维度 | 评分时某维度可标记跳过；总分计算时该维度取该维度 60% 中位分；榜单该单元格显示 Skip |

非目标：跨组权重方案、按组归档、导出 PDF/CSV、评分历史、暗色主题、工作台与榜单的结构改动。

**本轮去除**：覆盖率与「暂定」不再展示，也不再作为内部量保留——coverage/provisional 从两侧领域计算、API 响应、类型、榜单、工作台、评分弹窗、详情、对比、导出与测试中整体删除；排序同分次序由「覆盖率」改为「名称 → slug」。

## 2. v1.2 修订（吸收第二轮评审）

| 评审意见 | 处理 | 落地口径 |
|---------|------|---------|
| 组内出现 Skip 不应显示在组外 | 采纳 | 删除组列的 Skip 计数标记；组内跳过只影响组值本身，榜单不出现「n Skip」 |
| 组外应按要求算法计算分数 | 采纳 | 组值直接取综合分公式的组内约化：组值 = Σ(维度权重 × 换算分) ÷ Σ(组内参与计算维度权重)。分母与综合分同为「参与权重」，两者可互相还原；跳过维度按 60% 中位分进分子 |
| 维度设置 UI/逻辑不符合应有水平 | 采纳 | 维度设置按管理面板标准补足分组能力（见第 4 节），但范围限于增量（v1.4 收窄） |
| 成组只代表方便展示，不改变任何功能逻辑 | 采纳 | 组不参与综合分、不改变名次、不改变排序；唯一作用是榜单合并为一列 |
| 评分时组内维度应被相同颜色框住，不占视觉负担且各自独立评分 | 采纳 | 每组一个展示色（6 色常量，按组顺序稳定分配）；评分弹窗中该组每个维度行的左框线用组色，行内仍是独立输入与独立 Skip 按钮；组头显示组名与组内权重占比 |
| 排行榜中维度组按组内部维度在总分的占比排行 | 采纳 | 组列数值取该组在综合分公式中的组内约化值（参与权重加权平均换算分）；组列不新增排序键，官方名次仍由综合分决定 |

## 2c. v1.4 修订（吸收第四轮评审）

| 评审意见 | 处理 | 落地口径 |
|---------|------|---------|
| 跳过中位分没有前端数据通路 | 采纳 | 中位分由服务端按维度计算，随 rankings 与 model detail 的维度对象下发（字段 skipMedian，与 effectiveBaselineMax 并列）；前端与导出只消费该常量，不自行实现，故不存在双份实现漂移 |
| 隐藏模型是否参与中位分候选集 | 采纳并写死 | 参与：候选集 = 快照内全部模型（含隐藏）中未跳过该维度的有效分值；榜单、详情、预览与导出同源 |
| 组值口径与验收等式互斥 | 采纳 | 「组权重合计」定义为组内参与计算（有有效分值或已跳过）维度的权重合计；验收等式改写为「Σ(列参与权重 × 列值) ÷ Σ 参与权重 = 综合分」；无候选的跳过按 0 参与分母 |
| 批量成组与整组重命名没有接口 | 采纳 | 复用既有 PATCH /api/dimensions/{id}：按维度 id 串行提交，回执「已提交 x/y，失败项可重试」；不为批量新增端点 |
| 覆盖率移除遗漏详情与对比 | 采纳 | 详情页与对比页同步移除覆盖率与「暂定」；删除范围扩展到领域、API 与类型（见 2c 第 1 行与第 4 节） |
| 同分次序改动未落到前端预览 | 采纳 | Go sortRows 与 TS previewRanking 的比较器同步改为「综合分 → 名称 → slug」，两侧夹具与测试同步 |
| 跳过写入口径与既有评分写入不符 | 采纳 | 跳过写入沿用评分写入守卫：未知模型/维度 404，归档与文字维度 422，权重 0 维度允许写入（对计算无影响） |
| 文字维度入组前后矛盾 | 采纳（选排除） | 组集合只取「启用、非文字、权重 > 0」的维度；设置面板与维度弹窗对文字维度不提供组控件 |
| 工作台最小改动评估偏差 | 采纳 | 默认排序键改为「已评分」计数升序（替代覆盖率升序），综合分为空的行在任何排序方向下置顶；quickEdit.ts、scoreInput.ts 及其测试纳入 TASK-013 |
| 组色无值与对比度约束、色值分配放进 Go | 采纳 | 6 色固定值写入第 9 节（纸白底 5.14–6.47:1，满足 AA）；组色只在 TS 侧分配 |
| 待确认项无默认口径 | 采纳 | 第 9 节改为已定口径，无异议即按此执行 |
| 导出列范围与测试缺口 | 采纳 | 导出始终绘制全部启用列，不随视口隐藏列变化；导出布局为纯函数并附最小断言 |
| 维度设置面板超出本轮需求 | 采纳 | 收窄为增量：保留既有面板结构与行内权重展示，仅新增「维度组」列与多选分配；不做分段筛选、行内权重编辑与面板脚重构 |
| 组值 Go/TS 双份实现 | 采纳 | 组值只在 TS 侧实现（Go 无消费方）；Go 只负责跳过中位分与综合分 |

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 分组模型 | dimensions.group_name（TEXT，可空）；同名即同组 | 与「选几个维度起个组名」语义一致；建组/改名/拆组都是一次字段更新；无空组、无同步状态 | 独立 dimension_groups 表（多一层「先建组再建维度」） |
| 组集合 | 启用、非文字、权重 > 0 的维度中 groupName 非空者 | 文字维度没有数值列、权重 0 维度不计入总分，都不该产生组列 | 允许文字维度入组（组列无展示面，产生死列） |
| 组顺序 | 取组内最小 dimension.position | 复用既有排序，不引入第二套顺序来源 | 独立 position 列（两份顺序需同步） |
| 归属唯一性 | 一个维度至多属于一个组 | 组名是互斥归类，避免重复展示 | 多组归属（同一维度出现在两列） |
| 组列取值 | Σ(维度权重 × 换算分) ÷ Σ(组内参与计算维度权重) | 与综合分同为「除以参与权重」，量纲一致，可与综合分互相还原；缺分维度不进分子也不进分母 | 除以全组权重（缺分被稀释，与综合分口径不一致）／先算组再算总分（第二套口径） |
| 组是否参与总分 | 不参与。综合分仍由全部启用维度加权求和 | 保持「官方排名不随展示形式改变」 | 组优先（改变官方口径） |
| 组色的用途与主体 | 仅展示：榜单组头圆点、组内明细切换、评分弹窗组内维度左框线；TS 常量 6 色 | 捆绑关系可视化，且不改变任何计算；Go 无渲染消费方 | Go 侧分配色值（无消费方，双份实现） |
| 跳过存储 | score_skips(model_id, dimension_id) 主键表 | 跳过是评分状态而非分值；删除分值时跳过不被吞掉 | 复用 scores.note 或负分哨兵（语义污染） |
| 中位分计算主体 | 服务端 Go 按维度计算，随响应下发 skipMedian | 匿名榜单响应不含隐藏模型，前端自行计算会与综合分基于不同候选集；下发常量即 SSOT | 前端自行计算（数据通路不全，页面内自相矛盾） |
| 跳过计分 | 该维度换算分替换为下发的 60% 中位分 | 与需求直接对应 | 对中位数做 60% 缩放（改变量纲） |
| 跳过与权重口径 | 跳过维度仍计入综合分权重分母，并从「已评分维度」计数中移除 | 跳过是「已处理」，不应让总分分母缩水；该维度确实没有人工评分 | 从分母剔除（等同于把权重转移给其他维度） |
| 跳过写入守卫 | 沿用 UpsertScore 守卫：未知 404、归档/文字 422、权重 0 允许 | 与既有评分写入口径一致，不新增特例 | 额外拒绝权重 0（凭空多一条无收益规则） |
| 覆盖率 | 整体删除（域层、API、类型、UI、测试） | 展示与排序都不再用它，保留即为死状态 | 保留为内部量（无消费方） |
| 批量成组 | 前端 N 次串行 PATCH + 部分失败回执 | 复用幂等单条 PATCH，无需新增端点、事务与契约测试 | 新增批量端点（多一层接口与部分失败语义） |
| 导出实现 | 画布手绘（canvas 2d，2x 像素密度，从已加载排行数据生成） | 零新依赖；版式为纯色 + 1px 线，手绘稳定，不依赖 DOM 快照 | html2canvas / foreignObject（新增依赖或快照脆弱） |
| 组内明细入口 | 列头右缘小箭头（无边框、16×16 热区、绝对定位）触发抽屉，组与单维度共用 | 排序与查看详情各占一个控件，语义不再冲突；箭头不参与排布，列头文字对齐与列宽零影响 | 名称点击承担两义／带框按钮（挤压文字对齐）／表头原位展开（改列结构） |

## 4. 显示口径与系统行为（落地契约）

### 分组管理（维度设置，增量）

- 范围：在既有设置页维度列表上增量增加分组能力，不重构面板结构，不改变既有拖动/键盘排序、归档与维度弹窗编辑。
- 面板头：沿用既有标题、计数（n 启用 / m 归档）、显示已归档开关与「新增维度」按钮；不新增筛选分段控件。
- 列表列：拖动句柄 + 序号、维度名与说明、权重（只读文本）、**维度组**（下拉：不分组 / 已有组名 / 新建组名…，附组色示意）、已评分计数、操作（编辑 / 归档 / 删除）。
- 多选：行首复选框；选中后工具条显示已选维度名，提供「分配到组」「移出分组」「清除选择」。未选择时不执行批量写入。
- 写入口径：复用 PATCH /api/dimensions/{id}，多选按维度 id 串行提交，回执「已提交 x/y，失败项可重试」；整组重命名 = 选中该组成员后分配新组名；「不分组」只影响该维度。
- 文字维度与权重 0 维度不显示组控件（存值不入组，见第 3 节「组集合」）。

### 榜单

- 表头顺序：综合排名 / 模型 / 综合分 / 组列（按组顺序）/ 未成组维度列（按 position）/ 操作（不含覆盖率列）。
- 组列：组头 = 组色圆点 + 组名 + 明细入口，下方小字「n 项 · 权重 w」；列值 = 组值（2 位小数）；组值不显示 Skip 或 ★，组的跳过只体现在数值中。
- 组值 = Σ(维度权重 × 换算分) ÷ Σ(组内参与计算维度权重)；参与 = 该维度有有效分值或已跳过（取该维度 60% 中位分）；组内无参与维度显示破折号。Σ(列参与权重 × 列值) ÷ Σ 参与权重 = 综合分。
- 未成组维度列：一维一列，列头排序、权重标注、色阶与现状完全一致；单元格带组色左框线（未成组用中性色）。
- 列头结构（组与维度同构）：名称按钮承担排序（含方向与同分次序），其下第二行小字（维度为「权重 w」、组为「n 项 · 权重 w」）；明细入口为列头右缘外侧的无边框小箭头（10px 图标、16×16 热区），绝对定位在列间隙，不参与文字排布、不改变列宽与文字对齐。两个控件互不触发对方行为。
- 明细抽屉：组与单维度共用同一组件与同款入口，只有标题与元信息不同（组：维度切换 + 组值口径说明；单维度：单维度名次）。顶部维度切换按组色标记，下方该维度名次 / 模型 / 相对条 / 分值；跳过行弱色 Skip 排末尾。
- 移动端（≤760px）沿用现有维度列隐藏策略。

### 跳过（Skip）

- 榜单、详情、对比中的跳过单元格显示弱色 Skip，不显示数值与 ★。
- 60% 中位分（服务端按维度计算）：候选 = 快照内全部模型（含隐藏）中未跳过该维度的有效分值（有限且 ≥0），按该维度生效基准换算后升序取第 ⌊n×0.6⌋ 位，越界取末位；n=0 取 0。
- 该常量随 rankings 与 model detail 的维度对象下发（skipMedian，与 effectiveBaselineMax 并列），榜单、抽屉、评分弹窗预览与导出共用同一常量。
- 跳过维度的换算分替换为中位分，仍计入综合分权重分母；从「已评分维度」计数中移除；排序与名次按实际分值；跳过维度不参与该维度色阶与明细名次（明细排末尾并标 Skip）。
- 同分次序：综合分 → 名称 → slug（Go 与 TS 同步）。

### 评分台

- 工作台：不做结构调整。默认排序键为「已评分」计数升序（替代原覆盖率升序）；综合分为空的行在任何排序方向下置于可见行之前，隐藏模型仍排在可见行之后；列头排序保留。原覆盖率列位显示「已评分 x / 维度数」。分值单元格以弱色 Skip 展示；快捷编辑输入 Skip（不区分大小写）映射为跳过接口——quickEdit.ts 的值模型、scoreInput.ts 的解析与各自测试同步扩展。
- 评分弹窗：结构不变。摘要为综合分 / 综合排名 / 已评分维度；未评分（未评分且未跳过）的维度组整体上移，组内未评分维度在前并带「未评分」标记；每组显示组色与「组内权重占比 x%」；组内每行左框线为组色，行内仍是独立数值输入与独立 Skip 切换。预览使用响应下发的 skipMedian 与 effectiveBaselineMax 常量，标记/取消跳过后预览与保存后结果一致。

### 详情与对比

- 移除覆盖率与「暂定」；跳过维度单元格显示弱色 Skip。

### 导出图片

- 入口：榜单 billHead 内 compact 按钮（min-height 30px / 11px 文字）+ 内联图标，位于「新增模型」左侧。
- 内容：标题与统计口径、列头、全部模型行（综合排名 / 模型 / 综合分 / 组列 + 未成组维度列）；列集合为全部启用列，不随视口隐藏列变化；组值带组色标记；跳过单元格绘制为 Skip；底色字色沿用设计令牌；2x 像素密度。
- 列与坐标计算为纯函数（输入 Rankings + 组元数据，输出列集合与宽度），附最小断言；失败给出原因，不破坏榜单状态。

## 5. 阶段划分

### Phase 1：数据模型与接口层

| 项目 | 内容 |
|------|------|
| **输入** | 既有 dimensions/scores 表与迁移链（001–010） |
| **输出** | 011_dimension_group_name.sql、012_score_skips.sql；维度 groupName 读写（批量 = N 次 PATCH）；跳过读写接口；排行/详情响应的模型对象新增 skips，维度对象新增 groupName 与 skipMedian |
| **验收标准** | 迁移可重复执行且不改历史文件；写接口未登录 401；跳过对文字/归档维度 422、未知维度 404、权重 0 维度成功；includeHidden 语义不变 |

### Phase 2：领域计算与契约对齐

| 项目 | 内容 |
|------|------|
| **输入** | Phase 1 数据结构与快照输入 |
| **输出** | Go 侧按维度计算 60% 中位分并在综合分中替换跳过维度换算分；TS 侧由 groupName 派生组元数据与组值；两侧同分次序统一；coverage/provisional 全链路删除 |
| **验收标准** | 同一夹具 Go/TS 输出一致；跳过改变综合分、已评分计数减一；无跳过且无缺失时与旧实现逐位一致；Σ(列参与权重 × 列值) ÷ Σ 参与权重 = 综合分；两处不再出现 coverage/provisional |

### Phase 3：前端榜单与评分台（最小改动）

| 项目 | 内容 |

## 9. 已定口径（第四轮评审后，无异议即按此执行）

1. **覆盖率**：整体删除，含计算、API、类型、组件与测试；不保留内部量。
2. **组列排序**：按组值排序，与维度列同构；官方名次仍由综合分决定。
3. **Skip 与原值**：仅标记状态，不删除已录分值（可撤销）。
4. **组名**：trim 后 1–20 字符，同名即同组，空值即不分组。
5. **组色**：TS 常量 6 色 —— #2F6B4F / #1F5C8B / #8A5A16 / #6B4A8B / #8B3A52 / #3F6B6B，按组顺序稳定分配；纸白底对比度 5.14–6.47:1（AA 正文达标）。
6. **组集合**：只取启用、非文字、权重 > 0 的维度；文字维度与权重 0 维度不提供组控件。
7. **中位分候选集**：含隐藏模型，排除已跳过该维度的模型；无候选时取 0 并仍计入权重分母。
8. **跳过写入守卫**：沿用评分写入（未知 404、归档/文字 422、权重 0 允许）。
9. **导出列范围**：始终绘制全部启用列，不随视口隐藏列变化。
10. **批量成组**：前端 N 次串行 PATCH + 部分失败回执，不新增端点。

## 10. 设计哲学（Frontend 扩展）

- **选定哲学**：Microsoft Fluent 2 作为交互与可访问性基准（清晰层级、焦点可见、150–250ms 有目的过渡）。
- **视觉表达**：沿用项目既有瑞士/编辑式语言（纸白 #F2EFE6 / 墨黑 #14130F / 信号红 #B92A20、0 圆角、无阴影、1px 分隔线）；Fluent 令牌只补其未覆盖的交互细节。
- **分层**：Layer 0 纸白画布；Layer 1 榜单表格与设置面板；Layer 2 页头工具栏；Layer 3 评分弹窗与组明细抽屉（遮罩 + 1px 描边，无阴影）。
- **组件阶梯**：复用既有 Dialog / Button / IconButton / SortButton / Icon，不新增 UI 依赖。
- **Demo 范围**：靶向呈现组名分配与拆组、按参与权重取值的组列、组色框、Skip 文本、评分弹窗置顶与组色、小尺寸导出按钮；设置页只呈现计数 + 多选分配 + 组列，不做面板重构；工作台保持原布局。
