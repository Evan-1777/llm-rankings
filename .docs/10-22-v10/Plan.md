# Plan：详情相对条方向反转

**状态**：DONE（2026-10-22）  
**日期**：2026-10-22  
**版本**：v1.0  
**上游**：用户对详情页维度表的截图反馈（10-22-v9 交付后）

## 1. 背景与目标

v9 把详情页百分比模式的相对条改为与“差距”列同口径填充：最低分 100% 满格、最高分 1% 近零。该方案当时已在风险清单中登记“条越长 = 越差反直觉”，用户看到实际界面后确认不成立：模型越强，条越短。

目标：

- 百分比模式下，相对条改为越强越长：该维度最低分 0%、最高分 100%，中间值按得分在区间内的位置线性映射。
- 条方向与维度得分强调色阶（低分红、高分蓝）同向，消除“蓝色高分旁边一条近零的条”这一自相矛盾的呈现。
- 实际分值模式保持按最高分归一，不变。
- 同步说明文案、Project.md 事实与决策、自动化测试、归档与提交。

## 2. 方案与决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|---|---|---|---|
| 百分比模式相对条 | 新增 `scorePercentile`：`(value − min) / (max − min) × 100`，端点 0% / 100% | 与“越强越长”直接对应；最高分满格，和实际分值模式的“最高分满格”一致；与色阶同向 | `100 − gapPercentile`：最高分只有 99%，永远差一丝满格，端点语义含混；保留 v9 口径：用户已确认反直觉 |
| 百分比数字 | 保持 1% = 最高分 | 数字表达的是“距最高分的差距”，列头即“差距”，与本次反馈无关 | 一并反转数字：会把“差距”变成“得分位置”，改动面与需求不符 |
| 说明文案 | 百分比模式改为“分差百分比 / 1% = 最高分，100% = 最低分 / 相对条越强越长” | 相邻两列数值互补，必须显式说明条不按数字填充 | 保持“相对条同比例”：与实现矛盾 |
| 无有效区间（全同分、未评分） | 条宽 0，沿用 v9 | 无区间即无相对强弱，不伪造满格 | 沿用实际分值模式的全同分满格：百分比列显示“—”，条满格更难解释 |

## 3. 阶段划分

### Phase 1：相对条方向与文案

| 项目 | 内容 |
|---|---|
| 输入 | `web/src/lib/scoreEmphasis.ts`、`web/src/pages/ModelDetail.tsx`、既有分差百分比实现 |
| 输出 | `scorePercentile` 纯函数与单元测试；详情相对条宽度与说明文案 |
| 验收标准 | 该维度最高分条宽 100%、最低分 0%、中值按位置映射；未评分与全同分为 0；实际分值模式不变；`pnpm --dir web test` 与 `typecheck` 通过 |

### Phase 2：文档、归档与提交

| 项目 | 内容 |
|---|---|
| 输入 | 变更后的代码、Project.md |
| 输出 | Project.md 决策与测试记录、`.docs/10-22-v10/` 归档、按主题提交 |
| 验收标准 | Project.md 无与新实现冲突的旧口径；根目录无 Plan.md / Tasks.md 残留；工作区干净 |

## 4. 风险清单

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| 相邻“差距”数字小、条却长，被误读为比例不一致 | 🟡 中 | 说明文案明确“相对条越强越长”；条方向与色阶同向，可交叉校验 |
| 反向映射引入端点误差 | 🟢 低 | 纯函数 + 单元测试覆盖端点、中值、缺失、零区间 |
| 百分比模式下的全同分维度条宽 0 但实际分值模式满格 | 🟢 低 | 两种模式本就不同口径；全同分在百分比列显示“—”，零宽一致 |
