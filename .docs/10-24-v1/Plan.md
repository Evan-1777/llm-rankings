## 1. 背景与目标

排行榜下方增加可由管理员配置的公开文字区域，用于页面备注与评审规则，支持 Markdown。用户要求“只展示文字”解释为：不附加固定标题、提示、装饰图标、编辑按钮或预填正文；只显示管理员保存的内容。未配置时不显示空框或空白占位。

范围：一个站点级文本设置、现有设置页编辑入口、排行榜正文展示、存储与接口测试。正文初始为空，不代写规则。沿用现有单管理员与公开只读模型，其他设备刷新后生效，不增加实时同步。

非目标：富文本编辑器、预览切换、工具栏、版本历史、独立公告管理、公开开关、颜色/字号设置、Markdown 图片、GFM 表格/任务列表/数学公式，以及模型评语或私人备注的 Markdown 改造。现有 JSON 导出不包含显示设置，本轮不扩展导出格式，完整备份仍使用 SQLite 数据卷。

Phase 2 同时将设置页“完整 JSON 导出”文案收口为“模型与评分 JSON 导出”，只修正表述，不改变导出结构。

## 3. 架构与设计决策

| 决策 | 选择与依据 |
|---|---|
| 存储归属 | 扩展现有显示设置单例与完整 PUT，不新增资源、表或路由；一份已保存状态供设置与排行榜读取 |
| 字段契约 | 新字段为必传字符串；初始为空；服务端限制 20,000 个 Unicode 码点，约为模型备注 500 字符上限的 40 倍，同时限制每次公开配置读取的载荷；超限返回字段级 422，错误回填到文本框；原样保存换行与 Markdown，不 trim 正文，仅展示判空使用 trim |
| 编辑方式 | “设置 → 显示”末尾增加一个有标签的多行文本框和“保存”按钮；标签可标明 Markdown；不加 placeholder、示例、预览或教学文字 |
| 草稿与提交 | 本地草稿仅供输入；保存时携带已保存的三个站点开关；开关提交携带已保存正文，禁止顺带发布草稿；保存失败回滚共享状态且保留输入草稿；draft 与已保存正文不一致时拦截路径跳转与刷新，设置页内部 tab 切换不拦截 |
| 读取失败 | 首次读取失败显示可重试错误并禁用备注输入与站点保存；重试使用独立 retrying 状态，不复用全局 loading，避免卸载设置页或覆盖草稿 |
| 内容边界 | 复用成熟 React Markdown 组件，不自写解析器、不直接拼接 HTML；仅 CommonMark 文本结构，跳过原始 HTML 与图片，沿用解析器默认安全 URL 处理，不添加 raw HTML 插件；GFM 表格不在本轮范围 |
| 依赖取舍 | 现有依赖只有 React/路由，没有 Markdown 渲染能力；计划新增 react-markdown 10.1.0 一个直接依赖（peer react >=18，与当前 React 19.3.1 兼容）；不升级现有依赖、不引入 GFM/高亮/清洗插件堆栈 |
| 展示位置 | 排行榜主体之后（表格及原有表脚之外）、固定对比条之前；有正文时空榜单也显示；排行榜加载或失败时不把备注当作加载/错误反馈 |
| 设计哲学 | 沿用项目明确约定的 Apple HIG 交互与瑞士编辑式视觉；已有规范优先，不加入毛玻璃、圆角、阴影、渐变或新主色 |
| 层级与字号 | 备注是次级阅读内容，非独立卡片；距榜单约 24px，正文 14px、行高 1.75、弱色 ink-3，阅读宽度约 80ch；作者写入的标题最高约 18px，不变成第二个页面标题 |
| Markdown 排版 | 局部恢复全局 reset 清除的列表标记与缩进；段落/标题有统一间距，引用使用细线，链接有下划线及焦点，代码块内部横向滚动，长链接可换行；只作用于备注，不改其他页面 |

失败不会清空草稿或留下乐观发布的正文；其他页面刷新后读取同一份服务器配置。首次设置读取失败沿用公开页面的轻量降级，但必须让管理员看见读取失败并禁止基于默认值覆盖服务器内容；重试采用独立 retrying 状态，不触发全站 BootLoading，也不卸载设置页。此处不重构全站数据获取框架。

## 5. 风险与验证边界

- 完整 PUT 调用点与测试 helper 都需要新字段；逐一检索调用者，避免某个开关把正文清空。
- 读取失败默认为空并允许保存会造成覆盖风险；在设置写入入口阻止此情形，成功读取后再恢复编辑。
- 读取失败重试若复用全站 loading，会卸载设置页并丢失草稿；重试状态必须与初始加载分离。
- 显式保存引入未保存草稿：路径跳转与刷新必须提示，设置页内部 tab 切换不提示，避免长备注无提示丢失。
- 单二进制嵌入前端：前端构建必须先于最终 Go build，否则验证的是旧 dist。
- Markdown 是内容信任边界：验证原始 HTML、脚本协议链接与图片均不会产生可执行/外部媒体节点，不依赖 CSP 代替渲染安全。
- 全局 reset 清除了列表样式；必须恢复备注局部列表、标题和代码布局，否则语法解析正确但视觉不可读。
- 升级迁移只追加；验证已有单例行及旧开关值保留，不改已执行迁移，不插入默认文案。
- 保存中禁用站点开关与正文提交；失败保留草稿并能重试，不增加自动保存和多用户并发版本锁。

## 6. 依赖与 Subagent 协同

Phase 1 → Phase 2 → Phase 3。复杂度中低，改动跨前后端但沿一条设置调用链，状态/保存/展示决策强相关；各环节等待前一契约，不能形成足够独立的并行。启动子代理重读背景的成本高于收益，因此本轮不派发 Subagent，各 Phase 由主线串行执行；不为调度目的拆成独立后端/前端实现。

规划段完成后停止，等待执行模型或用户明确执行指令；不提前运行产品改动、归档或提交。本轮未显式启用 Frontend 扩展，不额外生成静态 Demo。当前项目事实文档不提前记载尚未实现的功能，由交付段同步。
