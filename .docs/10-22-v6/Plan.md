**状态**：DONE（2026-10-22 交付完成）  
**日期**：2026-10-22  
**版本**：v1.0  
**工作流**：Main-hybrid(Frontend)  
**设计哲学**：沿用项目既有的 Apple HIG 基线，视觉执行瑞士平面规范；不切换 Fluent 或 Material 3。

## 1. 背景与目标

当前排行、详情与对比页在维度得分上使用 6%–18% 的墨色透明度作为强调，颜色差异主要落在明度上，实际观感接近同一种米灰底，无法快速判断高分与低分。同时，所有只读表面仍直接展示实际评分，无法在不公开绝对分值的前提下比较模型之间的真实差距。

本轮引入可关闭的“百分比模式”，并把维度得分强调改为可辨红蓝和强弱的色阶。目标不是重做页面，而是在既有表格、排版与共享评分组件上增加一层显示契约。

### 1.1 需求解释与口径

**百分比模式**：

- 隐藏排行、详情、对比中的实际评分；综合分与各维度分都改为“分差百分比”。
- 以同一比较集合中的最高分为 1%、最低分为 100%，中间值按分差线性映射，而不是按名次等距分配。
- 公式：`gap = 1 + 99 × (max − value) / (max − min)`。
- 并列分值共享同一百分比；无有效分差（只有一项或所有值相等）显示破折号，不伪造 0%/100%。零分差与未评分共用破折号，二者都表示无有效差距，不新增第三个符号。
- 百分比保留一位小数，整数不显示 `.0`；真实最高分恒为 1%，真实最低分恒为 100%，舍入不得把非极值伪装成极值。
- 只改变显示，不改变排序、官方名次、覆盖率、加权计算、导出数据或任何接口。
- 管理员的评分工作台与评分弹窗保留实际分值；百分比模式服务于只读展示，不干扰录入与核对。
- 默认关闭，按浏览器保存；读取失败回到关闭，写入失败保留本次会话状态并提示。

**维度得分强调**：

- 依据实际维度得分在同一维度全榜范围中的相对位置着色，不依据百分比数字。
- 低分端使用暖红，高分端使用冷蓝；中点回到纸白；颜色强度随离中点距离增加。
- 高分仍对应“更好的成绩”，因此百分比模式下 1% 的最优模型使用高分冷蓝，100% 的最差模型使用低分暖红。
- 色阶只做辅助，不替代数字；文字保持墨黑，强制色彩模式与打印时移除底色。
- 默认保持开启，保留现有开关语义与本地保存。

### 1.2 目标

1. 设置页新增“百分比模式”开关，并与既有“维度得分强调”并列。
2. 排行、详情、对比三处只读评分表面统一支持实际分与分差百分比切换。
3. 维度强调色在低分与高分之间形成明确红蓝差异，低分为红、高分为蓝，数字对比度不低于现有正文标准。
4. 页面在 1440、900、760、390 宽度下无横向溢出，百分比数字不挤压关键列。
5. 纯函数测试覆盖线性映射、并列、零分差、极大值、舍入端点与色阶方向。

### 1.3 非目标

- 不新增后端字段、接口、数据库迁移或服务端偏好同步。
- 不改排名算法、覆盖率、暂定标记、评分精度或导出内容。
- 不为百分比模式新增图表、图例配置、阈值配置或暗色主题。
- 不改工作台与评分弹窗的录入数字；管理员仍需看到实际分值。
- 不引入新的 UI 组件库、字体或图表库。

**待确认口径**：本轮为页面展示层隐藏，公开的 `/api/rankings` 仍返回绝对分值。若要求对外不披露原始分，需要服务端过滤或新增百分位字段，属另一轮范围；开工前需确认。

**口径结论（2026-10-22）**：按浏览器本地显示偏好定性——百分比模式只改变页面数字格式，不在接口层过滤，也不新增站点级配置；对外不披露原始分不在本轮范围，事实记录于 `Project.md` 已知限制。

## 2. 显示契约

### 2.1 百分比作用面

| 表面 | 综合分 | 维度分 | 说明 |
|---|---|---|---|
| 综合排行 | 切换 | 切换 | 桌面维度列与移动端综合分列均生效 |
| 模型详情 | 切换 | 切换 | 大号综合分与维度表同步 |
| 模型对比 | 切换 | 切换 | 桌面表头与移动卡片同步 |
| 评分工作台 | 保持实际分 | — | 录入与核对场景 |
| 评分弹窗 | 保持实际分 | 输入保持实际分 | 不用百分比替代可编辑值 |

- 综合分的比较集合为所有具有有效综合分的模型。
- 维度分的比较集合为该维度所有具有有效评分的模型；未评分模型不参与极值。
- 暂定模型只要具有综合分，就参与综合分比较；覆盖率与暂定标记不变。
- 排序仍按实际分数执行；切换显示不改变行序。

### 2.2 色阶

- 端点：低分暖红（较差）与高分冷蓝（较好），中点透明纸白。
- 强度：由得分到维度中点的距离决定；中点无底色，离开中点即获得最低可辨强度，越接近最低分或最高分，底色与 2px 下划线越明显。
- 色阶强度只表达得分在维度内的相对位置，不表达分差百分比大小；两个高分模型即使分差百分比不同，也可以同为高分冷蓝。
- 文字：保持墨黑，不随底色变浅；端点底色上的文字对比度目标不低于 8:1。
- 辅助线：2px 内嵌下划线使用对应的饱和暖红/冷蓝，提供不依赖底色的方向提示。
- 图例：在排行与详情的评分区显示“低分红 → 高分蓝”小图例；设置页开关下显示同一图例。
- 可访问性：颜色不是唯一信息，数字本身仍可读；`forced-colors` 与打印移除底色和下划线。

### 2.3 文案与标签

- 排行表头“综合分”在百分比模式切换为“综合差距”。
- 详情页大号综合分标签切换为“综合差距”；维度表说明切换为“分差百分比 / 1% = 最高分”。
- 对比页在百分比模式下于大号数字上方显示“综合差距”，避免把百分比误读为原始分。
- 设置页两个开关保持短标签；“百分比模式”下方用“1% = 最高分 · 100% = 最低分”说明方向，“维度得分强调”下方用色块图例说明红蓝方向。
- 百分比说明统一使用“1% = 最高分”把差距数字与最高分语义显式连接，色阶图例使用“低分红 → 高分蓝”。

## 4. 架构决策

| 决策 | 选择 | 理由 | 未选方案 |
|---|---|---|---|
| 百分比映射 | 按最高/最低分差线性映射 | 直接体现模型分差；名次等距会把 0.1 分差与 2 分差显示成同样间距 | 按名次均分、按覆盖率加权 |
| 端点 | 1% 与 100% | 与需求一致，极值仍有可读数字，不与缺失值混淆 | 0% 与 100% |
| 零分差 | 与未评分共用破折号 | 没有分差时百分位无定义，且二者都表示无有效差距；不伪造 1%/100%，不新增第三个符号 | 全部 1%、全部 100%、新增「＝」 |
| 舍入 | 一位小数，端点保护 | 保留细小差距，同时不把非极值舍入成 1%/100% | 整数百分比、两位小数 |
| 偏好存储 | 浏览器 localStorage | 沿用现有显示偏好模型，个人自托管场景无需服务端同步 | 新增用户表/API 字段 |
| 作用面 | 三个只读评分表面 | 满足隐藏实际分的目标，同时不干扰管理员录入 | 全站所有数字、仅维度分 |
| 代码组织 | 一个共享评分显示纯函数模块 | 范围、色阶、百分比共用同一极值口径，避免三处各算一套 | 每个页面各写映射 |
| 色阶 | 红蓝发散色阶 + 文字保持墨黑 | 红/蓝直接区分高低，文字对比度不随背景下降 | 继续加深墨色透明度、红绿双色 |
| 百分比与色阶关系 | 色阶看实际得分质量，百分比看差距 | 最优模型在任何模式下都是高分冷蓝，最差为低分暖红；色阶强度只表达得分位置，不表达分差大小，避免把色阶误读为差距刻度 | 色阶跟随百分比数字，导致 1% 显示为暖红、100% 显示为冷蓝 |

## 5. 风险与处理

| 风险 | 处理 |
|---|---|
| 1% 最优、100% 最差与“高百分比更好”的直觉冲突 | 表头与说明统一用“分差/差距”，并明确“1% = 最高分”；色阶图例用“低分红 / 高分蓝”，避免把百分比当作得分 |
| 百分比舍入把第二名显示成 1% 或倒数第二显示成 100% | 格式化时做端点保护：非极值至少偏离端点 0.1 |
| 并列或零分差被误显示成差距 | 并列共享值；零分差与未评分共用破折号，表示无有效差距；测试固定 |
| 颜色成为唯一编码 | 保留数字与原排名；设置图例；强制色彩与打印去除底色 |
| 红色被理解为“错误”、蓝色被理解为“正常” | 与“低分差、高分好”的方向一致；图例明确“低分红 → 高分蓝”；色阶只用于维度分，不用于覆盖率或暂定状态 |
| 百分比字符串挤占移动端综合分列 | 综合分列使用较小字号/紧凑字距；390px 实测无横向溢出 |
| 存储失败导致设置丢失 | 保留当前会话状态并沿用现有 toast 路径 |
| 改动共享评分组件影响对比移动卡片 | 组件统一处理两种模式；浏览器覆盖桌面表与移动卡片 |
