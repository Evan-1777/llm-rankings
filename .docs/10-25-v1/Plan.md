## 1. 背景与目标

现状：综合分 = 已评分且权重 > 0 的维度原始分的加权平均，维度之间量纲不同（有的 10 分制、有的 100 分制）却按原始值直接相加，权重只能调整相对影响，无法表达“某维度满分是多少”。

目标：为每个维度引入可空的“基准最大值”，维度分先换算成百分制再参与加权平均：

- 换算分 = 原始分 ÷ 基准最大值 × 100，不封顶；超过基准时大于 100。
- 综合分 = 已评分且权重 > 0 的维度换算分的加权平均，可超过 100。
- 基准留空时取该维度当前所有已评分、未归档模型的最高分；填写时固定，可改可清空恢复自动。
- 原始分、展示口径、覆盖率、名次、同分、隐藏与归档规则全部不变。

本轮的两项已知取舍，需在交付时同步文档：

- 自动基准的候选集包含隐藏模型，因此可见模型的综合分会随隐藏模型的最高分变化；这是新行为，不是旧规则的自然延伸。
- 综合分从原始量纲变为百分制量纲；关闭百分比模式时，同一行的维度原始分与综合分不再同一量纲，界面标签与展示形式不变。

## 2. 现状与关键事实

- 评分与排名由 Go 领域纯函数计算，HTTP 层只做转换与序列化；前端只对“评分弹窗预览”重新计算综合分与名次，其余分值一律读接口。
- 排行接口返回维度 ID/名称/权重与模型原始维度分；模型详情返回逐维度原始分；导出复用同一维度响应结构。
- 维度响应结构被 bootstrap、创建、更新、归档与导出共用；写接口没有生效值的消费者，bootstrap 也不参与基准计算。
- 请求体类型不匹配由统一解码返回 400 malformed，字段级 422 只承载语义校验；评分写入同样如此。
- 评分弹窗的预览需要同时知道“全部已评分模型”的维度分才能推导自动基准；Workbench 已读取含隐藏模型的完整榜单，排行与详情读取的是公开榜单。
- 设置页维度列表为三档响应式网格，新增独立列会牵动三处断点布局。

## 4. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 自动基准的解析入口 | domain.EffectiveBaselines 纯函数，Compute、维度列表、导出共用 | 与“排名实时计算不落库”一致，单一事实来源；不另写 SQL 聚合 | 各处理器自行聚合（规则分叉）；只靠 Compute 顺带返回（列表含归档维度时取不到） |
| 生效值语义 | 配置值优先；自动且有有效评分 = 该最高分（全 0 时为 0）；自动且无评分 = 不返回（null）；换算时 null 或 0 均按 0 | 区分“全 0 维度”与“尚无评分”，设置页不臆造数值；与规则 4 一一对应 | 一律用 0（无法区分无评分）；一律用 null（丢失全 0 语义） |
| 维度载荷拆分 | 共享响应只带配置值；生效值由列表、排行、详情、导出按需计算并下发，写接口与 bootstrap 省略该字段 | 写接口无消费者，省略避免假值；需求明确要求排行/详情/导出返回生效值 | 所有响应统一计算（写接口多算一份且语义为空）；从排行/详情移除（违背需求） |
| 异常值口径 | 结构或类型错误沿用 400 malformed；0 与负数返回 422 字段错误 | 与评分写入及统一解码行为一致，避免为单个字段自定义解码 | 为非数字单独做 RawMessage 解码（收益低、复杂度高） |
| 前端预览数据源 | 父级声明榜单是否完整；不完整时读取含隐藏模型的完整榜单，失败时用详情的生效值兜底 | 自动基准包含隐藏模型；Workbench 已有完整数据，避免重复全量计算 | 无条件请求（重复开销）；只用传入榜单（隐藏模型场景失真） |
| 溢出口径 | 不封顶、不做非有限兜底；固定基准按现实量级使用并记入已知限制 | 自动基准换算 ≤100；只有管理员输入极端小基准与极端大分值才可能溢出，增加分支不划算 | 换算处按 0 或上限兜底（掩盖错误输入，且无实际场景） |
| 基准存储 | 可空 REAL 列，null 即自动；写入校验 > 0 | 与“留空=自动、填写=固定”直接对应，清空无需哨兵值 | 另设 auto 标志位（两列需同步）；用 0 表示自动（与全 0 语义冲突） |
| PATCH 清空语义 | 自定义可选值类型区分“缺省 / null / 数值” | 部分更新必须能分别表达“不动”和“恢复自动” | 增加 resetBaseline 标志（参数膨胀） |
| 设置页展示位置 | 维度行名称块的次要信息行，归档维度只显示配置值 | 不牵动三档断点网格，改动最小；归档维度的“生效值”没有产品含义 | 新增“基准”列（三处网格重排） |

## 8. 审阅意见处理

采纳：

- 统一 null/0/无评分/归档维度的生效值语义，消除四处互相矛盾的说法。
- 生效值不再由共享响应无条件携带：写接口与 bootstrap 省略，只在列表、排行、详情、导出计算。
- 基准解析收敛为 domain.EffectiveBaselines 唯一入口，Compute、列表、导出共用。
- 类型错误沿用 400，0/负数才返回 422，与现有解码及评分写入一致。
- 评分弹窗按需请求完整榜单，Workbench 不重复请求；失败时用详情生效值兜底。
- 补充隐藏模型影响公开综合分、综合分量纲变化、迁移清单、极端基准溢出与手工界面验收。

驳回：

- “导出只带配置值”：需求明确要求导出返回配置值与实际生效值，保留；导出中的归档维度按同一规则计算，作为恢复参考。
- “从排行/详情移除生效值”：需求明确要求排行/详情返回；详情另有预览兜底用途，排行作为契约字段保留。
- “换算处增加非有限兜底”：自动基准换算天然有界，极端固定基准属管理员自设输入，增加分支违背克制原则，改为记录已知限制。
