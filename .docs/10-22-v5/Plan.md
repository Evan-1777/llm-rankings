## 1. 背景与目标

主页及站内其他页面的页头当前提供“登录”链接，排行空态也提供“登录”按钮。目标是撤掉这些可见入口，登录页只保留为可直接访问的 URL（`/login`）；管理员仍可通过直接输入地址登录，未登录访问受保护页面时仍由路由重定向到登录页。

由于 `Header` 是全站共享组件，本次在组件源头删除登录链接，而不是按当前路径条件隐藏。这样“只能通过 URL 进入”在详情页、对比页等入口同样成立，也避免为单个页面增加路径分支。

## 3. 架构决策

- **共享组件源头删除**：登录链接只存在于 `Header` 一处，删除该分支即覆盖全部页面；不新增路径判断或登录开关配置。
- **路由保留**：`/login` 继续注册在路由表中，登录表单、限流、会话刷新与 `next` 回跳不变；不修改后端认证契约。
- **受保护页重定向保留**：`RequireAdmin` 在未登录时仍跳转 `/login?next=...`，这是访问受保护 URL 的自然结果，不是主页入口。
- **空态不放登录入口**：排行页的三处空态只保留管理员已登录时可见的操作；匿名用户看到管理员配置说明即可，不提供登录 CTA。
- **不采纳**：仅首页隐藏、其他页保留登录链接（仍可发现入口，与“只能通过 URL”冲突）；新增登录开关或环境变量（无此需求）；修改登录页视觉与流程（不在本次范围）。

## 4. 风险与处理

| 风险 | 处理 |
|---|---|
| 管理员失去页头登录入口，首次使用不便 | 这是明确需求；登录页仍可直接访问，受保护页仍会引导到登录 URL |
| 删除链接后页头留下空白或布局塌陷 | 保留会话容器的布局职责，只移除未登录分支；浏览器在 1440/390 视口验收 |
| 空态删除按钮后留下未使用的回调与导入 | 同步删除 `openLogin`；由类型检查与全量检索兜底 |
| 误删登录路由或受保护页重定向 | 检查 `App.tsx` 与 `RequireAdmin.tsx` 不在改动范围；浏览器直接访问 `/login` 与 `/settings` 验证 |
| 缓存导致浏览器仍显示旧入口 | 构建后由 Go 内嵌产物提供页面；验收使用新构建，不只依赖 Vite 旧缓存 |
