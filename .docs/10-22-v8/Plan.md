# Plan：评分工作台快捷编辑与站点级百分比模式

**状态**：DONE（2026-10-22 交付完成）  
**日期**：2026-10-22  
**版本**：v2.2  
**上游**：用户截图、2026-10-22 多轮反馈与只读评审

## 1. 背景与目标

评分工作台当前的编辑路径是逐模型打开评分弹窗：列表只显示综合分、名次、覆盖率与已评分数量，各维度分值不可见；补录或修正多个模型时，需要反复开合弹窗。截图要求增加快捷编辑模式，把分数就地铺开并允许直接修改，编辑期间不刷新排行，保存后再统一刷新。

后续反馈与评审暴露了以下问题：

- 第一版 Demo 在每行下方展开带边框的输入条，占用了过多垂直空间；编辑不应再引入第二套行高与重复标签。
- 工作台缺少表头排序，无法先按维度分值排列、再参考顺序编辑；排行页已有可复用的排序交互。
- 百分比模式只写入当前浏览器的 `localStorage`，换设备即失效；需要改为站点级持久化。
- 工作台当前是 `div` 网格，若直接复用排行页的 `<th>` 排序控件会出现 `aria-sort` 语义问题；需要先定结构。
- 排序方向与覆盖率未评分口径在 Plan、Tasks、Demo 中存在分歧；部分保存失败后的草稿基线也不诚实。
- 工作台面向桌面，不做移动端布局与验收；表格容器保留横向滚动这一结构性行为。

目标：

- 在 `/workbench` 增加可进入、可退出、可保存的快捷编辑模式。
- 工作台改为语义 `<table>`；维度分值常驻列；编辑模式只把同一单元格换成无边框输入，不新增行、不重复维度标签、不改变行高。
- 表头可单击排序，正常态和编辑态都能使用；编辑期间排序只重排视图，不重算、不刷新。
- 编辑期间保持综合分、名次、覆盖率与行顺序不变；保存成功后统一刷新并按当前排序重排。
- 不丢失已有评分备注；无效输入不写入；部分保存失败后只把未提交项计为未保存；未保存修改可拦截离开。
- 百分比模式改为站点级显示设置，其他设备刷新页面后一致生效。

## 2. 批判性吸收

| 设计输入 | 处理 | 理由 |
|---|---|---|
| 工具栏新增“快捷编辑”入口 | 采纳 | 入口贴近现有操作路径，且不新增页面 |
| 把分全部亮出来 | 采纳 | 维度列常驻；正常态即矩阵，编辑态复用同一单元格，避免模式切换时才出现信息 |
| 每行展开带边框字段 | 不采纳 | 垂直占用大、重复维度名与权重；改为无边框单行单元格，行高不变 |
| 模式内直接改分 | 采纳 | 复用非负、有限、保存时四舍五入到一位的既有评分契约 |
| 编辑期间不刷新排行 | 采纳 | 输入不触发 reload，也不做实时预览；综合分、名次、覆盖率冻结并降权 |
| 保存后刷新排行 | 采纳 | 保存成功 → 重新拉取排行与会话计数 → 退出模式，按当前排序重排 |
| 表头单击排序后再编辑 | 采纳 | 复用排行页的排序按钮/箭头/权重；工作台默认覆盖率升序，编辑态仍可点表头 |
| 同时显示“已评分”列 | 调整 | 并入覆盖率标签（`75% · 6/8`），保留信息且腾出一列给维度 |
| 大面积横向矩阵 | 采纳并约束 | 1440 桌面铺开参与排行的维度；工作台不做移动端布局，表格容器保留横向滚动 |
| 逐格即时保存 | 不采纳 | 写入放大、失败点分散；改为显式保存时按差分串行提交 |
| 在快捷编辑里改备注 | 不采纳 | 备注需要上下文与长文本输入，继续由评分弹窗承担；快捷编辑只改分值并保留原备注 |
| 新增批量保存接口 | 不采纳 | 现有单条写入可幂等重试，个人规模下串行提交足够；避免新增事务型接口与并发契约 |
| 百分比继续用 localStorage | 不采纳 | 这是跨设备失效的根因；改为服务端单例显示设置 + 公共读/管理员写 |
| 同面板的维度强调一起迁到服务端 | 不采纳（本次） | 用户只报告百分比；维度强调仍按浏览器保存，并在设置页标注作用域，避免未经要求扩大迁移面 |
| API 层按百分比隐藏绝对分 | 不采纳 | 这是显示偏好，不是访问控制；接口仍返回绝对分，工作台与评分弹窗始终实际值 |
| 跨设备实时推送设置变化 | 不采纳 | 其他设备刷新/重新打开后读取站点设置即可；不引入 WebSocket 或轮询 |
| 移动端工作台布局 | 不采纳 | 用户明确不需要；不做断点、卡片化或移动端验收；仅保留表格容器横向滚动 |
| 工作台保留 div 网格 | 不采纳 | 语义 table 与共享 `<th>`/`aria-sort` 最一致；当前 760px 卡片规则需随旧结构删除 |
| 新建 workbenchSort 排序模块 | 不采纳 | 复制 `sortRows` 的名称、缺失值、方向规则会漂移；扩展共享函数并加薄工作台包装 |
| 迁移插入 display_settings 默认行 | 不采纳 | 违反 Project 的零种子约定；迁移只建表，缺行读 false，写入 upsert |
| 部分保存失败后保留“全量草稿” | 不采纳 | 已提交项仍被当成未保存，取消文案与实际不符；逐项推进 baseline，退出时重载对齐 |
| 评审建议补 760/390 移动冒烟 | 不采纳 | 与用户“工作台不用适配移动端”的明确范围冲突；只删除旧断点，不做移动端验收 |

## 3. 范围与非目标

范围：

- 工作台语义表格、常驻维度矩阵、表头排序、快捷编辑、差分保存、部分失败基线、未保存防护。
- 评分写入契约扩展：省略备注时保留已有备注。
- 共享评分解析函数、快捷编辑草稿/差分/baseline 纯函数、共享排序函数扩展。
- 百分比模式站点级持久化：迁移、store、公共 GET/管理员 PUT、前端 Provider 与设置页作用域标注。
- 相关测试、桌面浏览器验收与 Project.md 同步。

非目标：

- 不做移动端工作台布局、断点或移动端验收；不承诺触屏编辑体验。
- 不把维度强调迁到服务端；本次只修百分比模式。
- 不修改排行、详情、对比页的只读展示；不把快捷编辑入口扩展到其他页面。
- 不新增批量接口、评分历史、撤销栈、导入导出或备注批量编辑。
- 不改变评分上下限、覆盖率与排名规则；不引入新依赖；不改变认证与权限模型。
- 不新增独立的工作台排序模块；不重复实现已有 `sortRows` 规则。
- 不做按用户/按设备的百分比设置；站点级设置对所有访客生效。

## 4. 交互与视觉

### 4.1 工作台结构与矩阵

- 工作台改为语义 `<table>`：`<thead>/<tbody>`、`<th scope="col">`、`<td>`；排序状态写在 `<th aria-sort>` 上，共享排序按钮放在 `<th>` 内。
- 普通态列顺序：模型｜参与排行的维度（权重 > 0）｜综合分｜排名｜覆盖率（含已评分 n/N）｜操作。
- 维度列常驻，表头显示维度名与权重；每格只显示一位小数分值，缺失显示“—”。数据直接来自 `/api/rankings`，不额外请求维度接口。
- 删除独立“已评分”列，把 `n/N` 放进覆盖率标签；N 取参与排行的维度数（权重 > 0），与覆盖率同口径。
- 表格外层 `overflow-x:auto`，首列 `position:sticky` 并带纸白底；桌面 1440 完整呈现。工作台不做移动端布局，删除现有 980/760 网格与 760 卡片规则，不保留移动端替代布局。
- 表格使用固定列宽（模型约 200px、维度 68px、综合/排名/覆盖/操作按现有密度），数据多时只让容器滚动；不引入横向页面滚动。
- 视觉沿用纸白、墨黑、信号红、0 圆角、1px 分隔线、等宽数字；不引入阴影或渐变。

### 4.2 表头排序

排序按钮/箭头/权重抽为共享 `SortButton`；排行页保留自己的 `<th>` 包裹与 URL 行为，工作台用自己的 `<th>`，两者 `aria-sort` 均落在语义表头上。

工作台排序契约：

| 键 | 首次点击 | 未评分模型 | 缺失维度/综合分 | 并列 |
|---|---|---|---|---|
| 模型 | asc | 按名称参与 | — | 名称、slug |
| 综合分 | desc | 置底 | 置底 | 正式排名、名称、slug |
| 排名 | asc | 置底 | 置底 | 名称、slug |
| 覆盖率 | asc | 按 0 参与；升序在前、降序在后 | — | 正式排名、名称、slug |
| 维度 | desc | 置底 | 置底 | 正式排名、名称、slug |

- 初始状态固定 `coverage asc`；同一键再次点击反转方向；新键按上表首次方向；默认方向不随“数值键一律降序”变化。
- 覆盖率是数值而非缺失值：未评分模型 coverage=0，升序自然在前、降序自然在后；缺失维度只指有综合分但该维度无分，恒置底。
- 排序只重排视图，不重算综合分/名次/覆盖率，不触发 reload；排序键与方向在进入/退出编辑、保存后保持。
- 编辑期间点表头只改行顺序，草稿随模型 slug 保留；输入不触发排序，只有显式表头点击才重排。
- 保存成功后刷新数据，按当前排序键与方向重排；表头箭头与 `aria-sort` 同步。
- 实现上扩展 `web/src/domain/ranking.ts` 的 `sortRows`：增加 `rank` 键与“未评分按 0/参与名称排序”的选项；工作台只加薄包装 `sortWorkbenchRows`，不复制比较器。排行页默认“未评分置底”的行为不变。

### 4.3 快捷编辑

- 工具栏“快捷编辑”以 `aria-pressed` 表示状态；仅在数据可用、存在模型、参与排行的维度且总权重大于 0 时渲染。
- 进入后隐藏“维度设置”“新增模型”和行内“编辑评分”；底部固定操作条承担取消/保存。
- 维度 `<td>` 在普通态是文本，编辑态变成同一尺寸的无边框 `input`：无边框、无外框、无新增行、无重复标签；预填一位小数，空值显示占位符。
- 输入接受有限、非负的任意精度；保存时四舍五入到一位小数（例如 8.75 → 8.8），不额外拒绝多位小数。焦点/改动/错误只用背景、2px 下划线与信号红表达；不在单元格周围画框。
- 编辑只更新本地草稿，不重新计算综合分、名次、覆盖率，不重排行；综合分、排名、覆盖率冻结并降低视觉权重。
- 表头排序在编辑态仍可用；行内操作列隐藏，固定操作条实时显示有效改动数；存在无效输入时禁用保存并指出第一处错误。
- 保存顺序固定为模型 slug 字典序 + 维度 id 升序，不随表头排序变化；新值/改值 PUT（不带 note，保留原备注），清空 DELETE，未变化不请求。
- 部分保存：按稳定顺序串行提交，每成功一项就把该单元格的本地 baseline 推进到提交值，已提交项从 dirty 移除；失败即停止，剩余项保持 dirty。底部显示“已保存 n 项 / 剩余 m 项未提交（其中 1 项失败）”，可再次保存补齐；派生值在编辑期间仍冻结。
- 取消或离开时只确认放弃剩余未提交项；若已有提交项，退出后 `reload()` 与 `session.refresh()` 对齐服务端，已提交项在普通态可见，未提交项不落库。全部成功时正常重载并退出。
- 保存失败但未提交任何项：保留完整草稿与原因；保存中禁用输入与操作。
- 有未保存改动时，取消、站内跳转与浏览器离开需确认；保存成功后不再拦截；退出/保存后焦点回到开关。

### 4.4 站点级百分比模式

- 根因：百分比只存在 `localStorage`，不是服务端事实；换浏览器/设备读不到。
- 新增单例 `display_settings` 表，字段 `score_percentage_mode`，默认关闭。迁移只建表、不插入种子行，遵守 Project 的零种子约定。
- store 读取缺行时返回 `false`（不是错误）；写入使用 upsert，首次开启时插入单例行；不依赖迁移预置行。
- `GET /api/display-settings` 公共读取（匿名页面也要显示同一模式）；`PUT /api/display-settings` 仅管理员，整对象写入；响应与请求均为 `{ "scorePercentageMode": boolean }`；GET/PUT 设置 `Cache-Control: no-store`。
- 前端 Provider 挂载时读取站点设置；设置百分比时乐观更新、PUT、失败回滚并 toast；读取失败回退默认（实际分值），不阻断页面。
- 设置页把“当前浏览器”改为逐项作用域：百分比标“所有设备”，维度强调标“当前浏览器”；百分比读取/保存期间禁用该开关。
- 百分比仍是显示模式：排行、详情、对比页使用；工作台与评分弹窗始终显示实际分值；API 仍返回绝对分。
- 站点设置对所有访客生效；其他已打开的设备刷新/重新打开后读取新值，不做实时推送。
- 升级后站点设置默认关闭，需要在设置页重新开启一次；旧浏览器 `llmrank:score-percentage-mode` 键不再读取，维度强调键保留。

### 4.5 备注与兼容

- 快捷编辑只改分值，不读写备注。
- 评分 PUT 的 `note` 改为可选：省略表示保留已有备注，显式空字符串表示清空；现有评分弹窗继续显式提交备注，行为不变。
- 新评分没有备注时写入空备注；清空评分仍删除整条记录。

## 6. 风险与缓解

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| 快捷编辑覆盖已有备注 | 高 | 写入契约保留备注，并以 API 测试锁定 |
| 编辑期间数值不动被误认为失效 | 中 | 派生值降低视觉权重，底部写明“保存后刷新排行”，并显示改动数量 |
| 排序在编辑中打乱草稿 | 中 | 草稿按 slug 保存；排序只重排视图；保存后按当前排序重排 |
| 部分保存后取消留下“看不见的已保存” | 高 | 每成功一项推进 baseline；取消只放弃剩余 dirty；退出 reload/session 对齐 |
| 多请求保存部分失败 | 中 | 串行提交、失败即停、幂等重试、保留未提交草稿并说明已保存/失败数量 |
| 未保存修改因跳转丢失 | 中 | 站内 blocker、beforeunload 与退出确认 |
| 语义表格改造引入布局回归 | 中 | 沿用排行页 table/滚动模式；删除旧 div 网格与移动端卡片规则；1440 验收 |
| 站点级百分比影响匿名访客 | 中 | 明确站点级语义；在 Project.md 记录；API 仍返回绝对分，不作为访问控制 |
| 设置读取前短暂显示实际分 | 低 | Provider 并行读取，失败回退默认；不阻塞全站首屏 |
| 升级后站点设置默认关闭 | 低 | 文档注明需在设置页重新开启一次；旧本地键不再读取 |
| 其他已打开设备未实时更新 | 低 | 明确刷新/重新打开后生效；不做实时推送 |
| 快捷编辑与评分弹窗、新增模型状态冲突 | 低 | 模式内隐藏这些入口；退出后重新建立草稿 |
| 桌面窄窗表格溢出 | 低 | 表格容器横向滚动、模型列吸附；不承诺移动端布局 |

## 8. 验收标准

- 工作台普通态使用语义表格，显示全部参与排行的维度列与权重；快捷编辑态同一单元格可改，无新增行、无边框输入框、行高不变。
- 表头排序覆盖模型、综合分、排名、覆盖率与各维度；排名首次 asc、覆盖率未评分按 0、缺失维度置底；编辑前后都可用；排序不重算、不刷新；保存后按当前排序刷新。
- 编辑期间综合分、名次、覆盖率与行顺序不变（显式表头排序除外）；保存成功后统一刷新并按新值重排。
- 已有备注在快捷编辑改值后保留；显式清空备注的既有路径不受影响。
- 空值删除、改值写入、未变化不请求；无效值阻止保存；部分失败只把未提交项计为未保存，取消/退出后已提交项保留、未提交项不落库。
- 百分比模式在一台浏览器开启后，另一隔离浏览器刷新可看到；匿名可读、匿名不可写；维度强调仍按浏览器保存；设置页明确标注作用域。
- 工作台按桌面 1440 验收；不包含移动端布局/移动端断点验收；旧移动端规则被删除，表格容器横向滚动只作结构行为。
- 自动化命令全部通过；Project.md 同步当前增量、接口语义、交互、作用域与已知限制，并改写被本方案推翻的旧决策。
