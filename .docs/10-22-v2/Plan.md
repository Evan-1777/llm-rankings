# Plan：维度手动拖动排序

## 1. 背景与目标
管理员在设置页拖动维度调整全局展示顺序，刷新后保留。排行、详情、对比与评分弹窗采用相同顺序；重排不改变评分、权重、综合分或模型排名。

本轮实现按计划交付：展示顺序持久化、稳定计分、原子重排接口与设置页拖动排序均已落地，并通过回归与浏览器验收。

## 2. 阶段划分
| 阶段 | 输入 | 输出 | 验收标准 |
|---|---|---|---|
| Phase 1：顺序存储与计算隔离 | 现有维度表、共享查询与评分算法 | 兼容旧库的展示顺序、稳定评分累加顺序、管理员重排接口 | 旧顺序保留，新建置尾，归档恢复保留位置；非法排列原子拒绝；重排前后得分与排名一致 |
| Phase 2：设置页排序 | 有序接口与现有维度列表 | 鼠标、触摸拖动手柄与键盘移动；保存反馈 | 有目标位置反馈；释放后保存；取消与同位置不请求；失败不应用新顺序；隐藏归档项保留槽位 |
| Phase 3：回归与交付 | 完整实现 | 回归记录、项目文档更新、归档与提交 | 后端测试与静态检查、前端测试/类型检查/构建通过；浏览器验收；无一次性产物 |

## 3. 架构决策
- 延续既有 Apple HIG 交互与可访问性基准、瑞士平面视觉规范，只增加行内排序手柄与交互反馈，不改版、不新增依赖。
- 在共享存储查询入口统一排序，数组顺序作为 API 展示顺序；不向每个页面重复加入排序状态。
- 增加独立展示位置，按原 ID 初始化；新维度追加末尾，归档及恢复保留原位置。
- 提交包含归档项的完整 ID 排列，在单个事务中验证数量、唯一性与成员一致性后保存；不分散为多条独立更新请求。
- 评分计算按稳定 ID 顺序累加，与展示位置分离，避免浮点舍入导致重排影响得分。
- 使用原生 Pointer Events 与 pointer capture，手柄提供方向键操作；只在释放时提交，不在指针移动时写库。首列在 >900px 为 60px、≤900px 为 44px；手柄分别为 52×44px、44×48px，将 grip 与序号合并展示；只在维度局部覆盖 IconButton 尺寸，不更改全站按钮。
- 长列表靠近视口上下 48px 时用 requestAnimationFrame 持续滚动，指针停留边缘仍继续；每帧按最新坐标更新目标，离开边缘或拖动结束立即停止。
- 使用现有加载与通知机制，成功后重载维度及会话；不额外创建乐观排序镜像。排序请求及其重载期间只禁用手柄和重复排序，CRUD 与归档筛选保持可用；维度数据/可见项变化时取消正在进行的拖动并停止滚动。
- 400 表示 JSON/类型解析失败；422 表示 ids 缺失、null、重复或非正 ID，返回 fields.ids；409 表示合法 ID 序列与当前维度集合不一致（含未知正整数 ID），不区分虚构与并发删除。409 自动重载服务端列表并通知，不用旧载荷自动重试。其他失败保持最近已加载列表，不应用请求中的未保存顺序；重载失败沿用错误重试入口。

## 4. 风险与处理
| 风险 | 处理 |
|---|---|
| 旧库升级改变原顺序 | 只追加迁移，历史位置按 ID 初始化；使用旧结构数据库验证迁移 |
| 调序影响浮点计算结果 | 前后端评分按 ID 稳定累加；验证数值与排名严格不变且不修改输入数组 |
| 过滤归档项后位置丢失 | 只重排可见项，再按原槽位合并完整 ID 列表 |
| 拖动中断、列表外释放或触摸滚动冲突 | 仅手柄禁用触摸默认行为；取消、失去捕获及无目标释放不保存；普通行可滚动 |
| 保存期间重复操作或列表已变化 | 只禁用排序；CRUD/筛选保持可用；事务校验完整集合，409 自动重载并通知；重载期间继续阻止排序 |
| 手柄超过移动序号列宽 | 同步调整维度表头及行首列到 60/44px，仅局部覆盖手柄尺寸，保留生产操作列；覆盖 1440/900/760/390px |
| 长列表无法跨视口移动 | 15 个以上维度验收持续边缘滚动、目标更新及结束清理，不照搬 Demo 的仅 pointermove 触发滚动 |
