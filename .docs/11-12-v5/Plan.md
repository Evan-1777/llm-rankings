# Plan：榜单对齐收口

**状态**：DONE
**日期**：2026-11-12
**版本**：v1.0
**完成日期**：2026-11-12
**回归测试结论**：自动化基线全绿 —— `go test ./...`（64 个测试函数全绿）、`go vet ./...`、`CGO_ENABLED=0 go build ./cmd/server`、`pnpm --dir web test`（72/72，新增导出图片右锚点断言）、`pnpm --dir web typecheck`、`pnpm --dir web build`、`gofmt -l cmd internal` 无输出。浏览器在 1440 / 768 / 390 三视口用临时库真实数据逐列读回几何量：名次数字墨迹左缘收敛为单值、表头首行墨迹顶收敛为单值、评分列宽收敛为单值（1440 下 107.3px）、列头文字右缘与列内数字右缘偏移为 0、排序激活前后同一列头文字右缘不变、三视口页面级无横向溢出。

## 1. 背景与目标

用户反馈：榜单对齐是遗留问题，大量元素没有对齐，观感难受，要求全部修复。

用浏览器在 1440 / 768 / 390 三视口对真实数据榜单逐列读回几何量（表头首行墨迹位置、列宽、取值框左右缘与宽度、取值数字右缘、左侧分隔线位置、名次文字左缘），确认的不是单一缺陷，而是五类可复现的不对齐：

| 编号 | 现象 | 证据（1440，CSS px） |
|------|------|----------------------|
| A | 第 1 名的名次数字相对其它行右移 11px | 名次文字左缘集合 `[35, 24]`：第 1 名行名次条参与行内布局，占位 3px + 间距 8px |
| B | 表头首行不在同一条基线 | 两行表头（评分列）首行墨迹顶 343；单行表头（模型、综合分）349.5；综合排名 350.3；差 6.5–7.3px |
| C | 当前排序列的列头文字被排序箭头挤走 16px | 综合分列头 label 宽 61.8 = 文字 + 5px 间距 + 11px 箭头，文字右缘 499.8，而同列取值右缘 515.8 |
| D | 列头文字右缘与列内数字右缘错位 9px | 组列列头右缘 728.9，组值数字右缘 719.9；全部评分列偏移量恒为 9（取值框右内边距），未着色单元格（组值、破折号、Skip）肉眼可见 |
| E | 评分列宽不齐、取值框与左侧分隔线随内容漂移 | 列宽 `102.9 / 116.4 / 102.9 / 102.9 / 140.4 / 102.9 / 102.9`（长维度名把该列撑宽）；同一列内取值框宽度 `{58, 59}` → 分隔线左缘出现 `{544.5, 543.5}` 的双值 |

目标：让榜单的每一条对齐关系都落在一个确定锚点上——名次共用一条左缘、表头首行共用一条基线、列头文字压在列内数字上、评分列等宽从而取值框与分隔线成规则网格。

## 2. 阶段划分

### Phase 1：表头与名次对齐

| 项目 | 内容 |
|------|------|
| **输入** | 榜单表头结构（共享排序控件 + 名次静态表头）、名次单元格 |
| **输出** | 名次标记在每一行都占位；每个表头都保留副行位置，首行共用一条基线；排序箭头不再挤动列头文字 |
| **验收标准** | 名次文字左缘集合收敛为单值；表头首行墨迹顶集合收敛为单值；激活排序列与未激活时列头文字右缘不变 |

### Phase 2：列网格与取值锚点

| 项目 | 内容 |
|------|------|
| **输入** | Phase 1 之后的榜单表格布局与取值框样式 |
| **输出** | 评分列等宽网格；列头文字右缘压在列内数字右缘；导出图片中数字列表头与 Skip 与数值同锚点 |
| **验收标准** | 评分列宽集合收敛为单值；同一列内取值框宽度、分隔线左缘集合收敛为单值；列头文字右缘与列内数字右缘偏移为 0；导出画布中数字列表头与 Skip 右对齐 |

### Phase 3：测试、文档与归档

| 项目 | 内容 |
|------|------|
| **输入** | 前两阶段的改动 |
| **输出** | 基线结论、三视口浏览器验收结论、与代码一致的 Project.md、归档与提交 |
| **验收标准** | 验证基线全绿；三视口页面级无横向溢出；Project.md 与实际一致；Plan/Tasks 归入 `.docs/11-12-v5/` |

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 第 1 名的名次条如何不挤动数字 | 名次文字元素在每一行都带一个同尺寸的标记位，仅第 1 名上色 | 标记位本来是行内元素，只在第 1 名存在 ⇒ 只有那一行的数字被推走；把占位变成恒定，根因消失 | 把标记改成绝对定位再给单元格加左内边距：改动面更大，且要另找对齐目标 |
| 表头首行基线 | 排序控件恒定渲染副行（无副行时留空占位），表头单元格内容居中、上下留白由单元格内边距给出 | 基线错位的根因是「有没有副行」改变了整块高度；占位恒定后所有列头等高，居中即基线一致；长标签换行时单元格按内容增高，首行仍停在原处 | 把所有表头改成顶部对齐：换行标签会把首行往上顶；给每个表头手写不同的内边距：把差异写成常量 |
| 排序箭头位置 | 箭头恒定渲染（未激活时仅隐藏），右对齐列头把箭头排在文字左侧 | 文字右缘恒定压在列内数字上，且切换排序不再跳动 | 箭头留在文字右侧：激活时文字被挤走（即当前缺陷）；不渲染箭头时占位：仍然跳动 |
| 列头文字与列内数字的锚点 | 文字对文字：列头右内边距取取值框的右内边距 | 列头服务的是它下面的数字；取值框只是底色块，把块边缘当锚点会让未着色单元格（组值、破折号、Skip）整体错开 9px | 保持现状（块边缘对齐）：不满足「全部对齐」 |
| 评分列宽度 | 榜单改用固定表格布局，评分列声明同一宽度，富余宽度按比例摊给全部列 | 变宽由内容（长维度名）驱动 ⇒ 列宽、取值框间距、分隔线位置全部随之漂移；固定后评分列恒等宽，取值框与分隔线成规则网格（工作台已是同一做法） | 保持自动布局：长维度名所在列永远比邻列宽，网格无法成立 |
| 长维度名 | 评分列列头允许换行 | 列宽固定后长名只能换行或截断；换行保留完整信息，截断会藏信息 | 截断加省略号：首屏丢失维度名 |
| 取值框内边距来源 | 提到全局设计令牌，列头与取值框共用 | 两处必须恒等，令牌是单一事实来源 | 两处各写 9px：改一处就会再次错位 |
| 导出图片 | 数字列表头与 Skip 一并改为右对齐，与列内数值同锚点 | 导出即榜单的另一视图，同一类错位（表头左对齐、Skip 左对齐） | 只修页面：导出图仍保留同类错位 |

## 4. 风险清单

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 固定表格布局在窄视口压缩不了列宽，表格改为容器内横向滚动 | 🟡 中 | 评分列声明宽度取小值，使 1280 视口仍可容纳；三视口验收确认页面级无横向溢出（表格容器自身滚动是既有行为） |
| 长维度名换行抬高表头行高 | 🟢 低 | 表头行高按内容增长，首行位置不变；三视口截图核对 |
| 组列的副行文字（「n 项 · 权重 w」）比固定列宽的可用宽度更宽 | 🟢 低 | 副行右对齐，超宽时向列内左内边距溢出，不进入邻列文字；桌面宽度下可用宽度足够 |
| 共享排序控件同时服务工作台 | 🟡 中 | 副行占位与箭头位置在共享控件内修正，工作台同样受益；简化换行类时同步核对工作台表头不被破坏 |
| 取值框宽度随内容在 58/59 间变化 | 🟢 低 | 固定列宽后同一列的偏移只剩 1px（亚感知），不再叠加列宽漂移；本轮不为此给数值框写死宽度 |

## 5. Phase 依赖关系

```
Phase 1 ──→ Phase 2 ──→ Phase 3
```

Phase 1 与 Phase 2 都动榜单表头结构，串行推进；Phase 3 在样式定型后统一验证、记录与归档。

## 6. Subagent 协同规划

对照三维效益模型（任务复杂度、上下文关联度、经济与时间效益）评估本轮委托需求：

| 阶段 | 上下文依赖 | 并行收益 | 执行主体 | 决策理由 |
|------|-----------|---------|----------|----------|
| Phase 1：表头与名次对齐 | 强（依赖本轮几何量测结论与共享控件约定） | 无 | 主线 | 改动集中在三处小差分，隔离会话重载上下文的开销高于改动本身 |
| Phase 2：列网格与取值锚点 | 强（列宽取值需与量测结果联动） | 无 | 主线 | 需边改边量测列宽与偏移，属强交互链路 |
| Phase 3：测试与文档 | 中（结论须复述本轮判定） | 低 | 主线 | 验收结论与文档须复述量测数据，拆给隔离会话需重复交代 |

> **协同结论**：本轮为同一条链路上的对齐收口，改动小但强依赖会话内的量测与判定，全部由主线推进；不派发 Subagent。
