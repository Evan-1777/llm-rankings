## 1. 背景与目标

本轮输入有三项：

1. 模型详情页的相对条在维度最高分低于 10 时无法满格，当前按 10 分下限归一。
2. 详情页新增同维度排名，沿用现有瑞士平面排版、等宽数字与移动端列策略。
3. 吸收工作流 Review 报告（87/100）的可用意见，修复前几轮残留。

目标是让评分预览与落库排名共用同一比较契约，让评分弹窗和设置页的反馈、数据口径自洽，并把归档文档整理到可追溯状态。不为单管理员场景新增批量接口、事务层或额外状态机。

## 3. 架构决策

- **同分比较契约**：前端名称比较改为小写后按位比较，与 Go 的小写字节序在常规文本上同序；不修改后端排序规则，因为后端是落库排名的权威，改前端是更短的有效差分。slug 仍作最终兜底，两侧各留中文同分 fixture 防漂移。
- **相对条**：移除 10 分下限，按本维度实际最高分归一，最高分（含并列）恒为满格；全 0 维度保持零宽，不制造虚假差异。详情页说明文字同步移除“下限 10”。
- **维度排名**：由已加载的排行快照在前端纯函数计算，不新增接口；只统计该维度已评分的模型，按分值降序、名称/slug 次序编号，与官方排名共用同一比较契约。详情页以右对齐列呈现“名次 / 已评分模型数”，移动端保留。
- **备注归属**：备注属于评分行，评分输入为空时禁用备注入口并隐藏编辑区；不新增“仅备注”的存储或接口。
- **完整度口径**：设置页模型行的分子与分母都限定为“启用且权重 > 0”的维度；`scoreCount` 仍表示全部已存评分，用于页头与数据页的总数，避免总数被归档评分吞掉。两者拆开，不共用一个字段承担两种含义。
- **空态**：页面空态只依据本页已加载的数据；bootstrap 计数只作为加载完成前的占位，跨请求失败不改变页面事实。
- **失败反馈**：保存失败提示区分“未提交”与“已提交 N 项”；评分 DELETE 改为幂等，使多请求保存的重试可以收敛。不引入批量保存接口。
- **归档文档**：修正 v2 任务状态与交接段落，重写 v2/v3 相对链接，补齐 v1 TASK-026 验收。只消除与最终状态冲突的陈述，不改写已验证的历史事实。
- **不采纳**：设置页三套排序状态合并为单一 `finally`（会把“重载完成前禁止排序”的既有要求降级，并可能在并发 CRUD 重载时提前解禁）；导出加读事务（个人备份场景，改为把“快照”文案修正为“导出”）；批量保存接口（单管理员，收益不足）。

## 4. 风险与处理

| 风险 | 处理 |
|---|---|
| 修改名称比较后视图排序变化 | 只影响同分/无排名时的次序；用中文同分 fixture 固定契约，官方分组数不变 |
| 相对条失去下限后低分维度差异被放大 | 该条本就是维度内相对量；说明文字明确“按最高分归一”，不参与综合分与排名 |
| 新增排名列挤压移动端表格 | 移动端只保留维度、权重、得分、名次；760px 以下隐藏相对条，390px 验收无页面横向溢出 |
| 完整度口径改动影响总数 | 保留 `scoreCount` 总数字段，另加可评分维度计数；页头与数据页总数不变 |
| 备注入口受限后无法先写备注 | 备注只能附属于评分；评分留空即删除评分与备注，语义一致 |
| 归档文档改写引入事实错误 | 只按代码与提交记录修正状态、链接和缺失验收；链接用脚本逐条检查 |
| 删除幂等改变 API 行为 | DELETE 评分重复调用返回 204；未知模型仍 404；补 API 测试固定语义 |
