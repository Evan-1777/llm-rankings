## 1. 背景与目标

用户对上一轮（`.docs/11-12-v2`）的判定：方向做反了。上一轮把组列独有的 `.groupValue`（`font-family: var(--font-mono)`、`font-variant-numeric: tabular-nums`、15px）**合并进了维度列的 `.dimValue`**，而 `.dimValue` 是榜单全部评分列共用的单元格类——等于把组列的样式铺到整张榜单；同时组列本身并没有真正用上维度列的取值样式。

根因：维度列的等宽字体与取值框来自取值组件 `DimensionScore` 的 `.score` 元素（`font-family: mono` + `font-variant-numeric: tabular-nums` + `min-width`/`padding`），组值却是一段裸文本，因此历史上（v1 的 `.groupValue`、v2 的合并写法）都在用重复声明去补这个缺口。

本轮按其要求收口：

- **还原**：`.dimValue` 回到 v2 之前的定义（仅 `font-size: 14px`），维度列样式零改动。
- **同化**：组值改用维度列同款的取值元素（`DimensionScore` 的 `.score` 框），组值仍按换算分两位小数渲染。

目标：榜单上组列与维度列在列宽、列头、取值框、字体与数值口径上一致；榜单样式表里不再出现任何「组专属」的取值声明，也不再有任何「为补组列而改维度列」的声明。

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 组值如何取得维度列的取值样式 | 复用取值组件的 `.score` 类（`import scoreStyles from "../components/DimensionScore.module.css"`），组值渲染在同一取值框内 | 维度列取值的等宽字体与内边距本来就在该元素上；复用即「组列被同化」，且维度列所在样式表零改动 | 继续在 `Rankings.module.css` 里重复声明等宽：v1 的 `.groupValue`、v2 的 `.dimValue` 合并都是同一条错路的两次变体；给 `DimensionScore` 增加新属性：为一次性复用扩张组件 API |
| 维度列样式 | `.dimValue` 还原为仅 `font-size: 14px` | 维度列的等宽来自 `.score`，v2 加进 `.dimValue` 的声明对维度列是冗余、对组列是错源；还原后维度列 DOM 与样式回到 v2 之前 | 保留 `.dimValue` 的等宽声明：仍是把组列样式写在共用类上 |
| 组值显示口径 | 不改：仍为换算分两位小数，不接入百分比与色阶 | 组值由 `formatScore`（两位小数）渲染，与综合分同一口径；接入百分比/色阶需为组引入区间与最大值来源，属显示口径变更，超出本轮「样式方向」的反馈 | 组值改走 `DimensionScore`：该组件默认用 `formatDimension`（一位小数）且百分比模式在缺区间时返回「—」，会同时改动数值口径与显示结果 |
| 榜单是否还保留组专属样式 | 全删：`Rankings.module.css` 不出现组专属取值类 | 用户要求组列不能特殊 | 保留（哪怕只剩一处）：仍会被视为特殊 |

## 4. 风险清单
