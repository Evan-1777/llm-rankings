## 1. 背景与目标

LLM Rank 是一个单管理员维护、公开只读的模型评分与排行 Web 服务。交付目标为 Go 单二进制、React 前端、SQLite 持久化，最终由 Docker Compose 部署到个人 VPS。

首轮修订确立了四项方向：

1. 删除多套「评分方案」及其选择器，只保留一套全局维度权重。
2. 排行表列名本身即排序控件，支持正序与倒序，不增加排序下拉框或额外入口。
3. 移除占据三栏的权重侧栏，把权重降为维度列名下的微型标注与页头总量；榜单恢复全宽。
4. 使用用户提供的专属图标作为页头品牌标识与站点图标。

本轮继续修订，收敛管理端与视觉密度：

1. 维度必须在独立设置页中增减；新增、编辑、归档、恢复与永久删除都留在设置页完成。
2. 设置页独立于排行，评分统一由评分弹窗填写，不再维护内联评分表。
3. 管理员在排行榜与详情页直接获得评分入口：已有评分进入编辑，未评分模型进入新增。
4. 版面降低刊头字号、增加区块间距与表格行高，并提高最小功能字号，减少连续阅读压力。

第三轮补充：

5. 排行榜、工作台与设置页提供明确的「新增模型」入口，共用模型表单；该按钮不承担评分，评分仍由模型行内入口进入。
6. 单维度评分不设上限，仅要求非负有限数并保留一位小数；综合分可以超过 10。
7. 详情页移除固定 10 分刻度的条，改为按当前维度最高分与 10 的较大值归一的相对条，仅作视觉参考，不参与计算。

第四轮审查修订：

8. 无上限评分是用户明确要求，保留；改为先归一权重再乘分数，避免有限极大值溢出，不引入人为业务上限。
9. 覆盖率 80% 暂定保留为展示策略；显示与阈值统一向下截断到一位小数，79.9% 不再显示成 80%。
10. 不设维度硬上限；多列表格内部横向滚动。权重 0 维度在设置页标「不参与」，不进入评分弹窗。
11. 补齐执行契约：SQLite NOT NULL/CHECK 与逐连接 PRAGMA、反代 Host/Origin 与可信 IP、totalWeight=0 响应、updatedAt、未评分行置底、草稿离开保护、中文名 slug 回退、dist 占位文件。
12. 文本信号红改为 #B92A20（对纸白 5.35:1）；功能文字与徽标不小于 10px；移动主按钮 44px、行内图标 34px。
13. 删除 PUBLIC_READ 与未使用的搜索图标，收敛重复验收；增加前端纯函数 node --test。

最终闭环：

- 空数据库启动后显示无数据空状态，不出现种子内容。
- 管理员登录后可在设置页创建维度与权重，并从排行、工作台或设置页新增模型；在排行榜、详情或工作台打开评分弹窗完成评分与私人备注。
- 匿名访客可查看全宽加权排行、切换列排序、查看模型详情与对比。
- 排名实时计算，不落库；覆盖率低于 80% 标记「暂定」。
- 管理员可导出完整 JSON 快照。
- Go 测试、前端 typecheck/build 通过；镜像构建由 GitHub Actions 验证。
- 视觉与交互达到可直接上线的成熟产品表面，不依赖 UI 组件库或图表库。

### 非目标

多用户、注册、OAuth、历史评分、自动 benchmark、AI 评分、评论社区、JSON 导入、国际化、暗色主题、原生 App、Flutter Web、图表库、多评分方案或用途切换、独立内联评分表。

## 2. 设计与信息架构

### 2.1 设计哲学

以 **Apple HIG** 作为交互与可访问性基准：清晰层级、克制反馈、精确状态、完整键盘支持。视觉执行项目既定的 **瑞士平面风格**：

- 纸白、墨黑与单一信号红；不使用渐变、阴影、发光。
- 12 栏网格、1px 分隔线、零圆角；字体、留白、对齐和线条建立层级。
- 刊头保留编辑式节奏，但不再以超大字号占据首屏；数据表获得更多呼吸空间。
- 中文界面优先，模型名与厂商保留原文；数字使用等宽字形；不下载远程字体。
- 已加载 engineering-discipline、frontend-design、production-frontend。Apple HIG 无独立 Skill，视觉令牌依项目规范执行。

### 2.2 品牌图标

用户提供 512×512 PNG 图标，内容为圆形山景与犬只标识，具有蓝、黄、绿等既有色彩。

- 生产资源复制为 `web/public/brand-icon.png`，不从 temp 直接引用。
- 页头左侧使用 32px 圆形裁切（≤760px 为 28px），与「LLM RANK」文字组成品牌锁定；登录页使用 56px。
- 作为 favicon 与 apple-touch-icon；不重绘、不调色、不加滤镜。
- 图标是唯一允许的圆形视觉元素；界面组件仍保持零圆角。
- 图像仅作品牌识别，不进入数据、评分或排行计算。

- 对比模型上限 4 个；选择保留在 URL，可从排行底部对比栏或详情页进入。

- 所有页面具备空、加载、错误、成功四态；空态直接给出下一步动作，不写教学文案。

### 2.5 排行页与排序

排行页采用全宽结构：

1. 刊头：大标题「综合排行」；右侧保留维度数、权重合计、模型数、已评分数量与更新时间。字号收敛，留白增加。
2. 榜单标题行：当前榜单、加权平均说明；管理员态追加「新增模型」按钮，打开共享模型表单。
3. 全宽数据表：综合排名、模型、综合分、覆盖率、各维度、操作。
4. 页脚：暂定规则与权重合计。

权重只在两处出现：

- 维度列名下方 10px 的权重数字，与列名共同构成排序按钮。
- 刊头与页脚中的权重合计。

不再有独立权重侧栏、权重条形图或方案说明卡。

排序规则：

- 可排序列：模型、综合分、覆盖率、每个维度；综合排名列不参与排序。
- 直接点击列名即可切换；不增加下拉框、排序按钮或工具栏入口。
- 数字列首次点击按降序，第二次切换升序；模型名首次按升序，第二次降序。
- 空值固定排在最后，不随方向翻转。
- 未评分行不参与列排序，始终置于已评分行之后；覆盖率升序不会把未评分行带到顶部。
- 覆盖率显示向下截断到一位小数（整数时省略小数）；79.9% 显示为 79.9% 并保持暂定，不能显示成 80%。
- 第一列始终显示按加权综合分计算的「综合排名」，不随当前排序重编号；列名明确写为「综合排名」。
- 激活列使用墨色文字与信号红箭头；桌面表头 58px 点击区、移动端 50px，键盘焦点在重绘后回到原列。
- 综合分固定显示两位小数，维度分固定一位；输入、存储与加权计算不截断。
- 排序状态写入 URL 的 sort 与 dir 参数，刷新与回退可复现。
- 排序重绘不播放整页入场动画，避免榜单闪动。

管理员操作：

- 操作列在排行榜末尾，管理员可见两枚 30px 图标按钮：对比选择与评分入口。
- 已有评分的模型显示铅笔图标与「编辑 <模型> 评分」可访问名称；未评分模型显示加号与「为 <模型> 添加评分」。
- 点击评分入口打开评分弹窗，不改变当前路由。
- 标题行提供「新增模型」按钮；创建成功后留在当前页，新模型以未评分行出现，不自动打开评分弹窗。
- 匿名态不渲染新增模型与评分按钮，只保留对比入口。

移动端：

- 只显示综合排名、模型、综合分、覆盖率与操作；隐藏维度列。
- 360–430px 下固定列宽合计不超过内容宽度，页面无横向滚动；模型名可换行。
- 可见列仍可直接点击排序，不增加移动端排序选择器。

### 2.6 详情、对比与工作台

- 详情页：综合分与事实区之后维度表全宽展开；权重仅作为小号列；评分无固定上限，维度表的最右列按该维度最高分与 10 的较大值归一的相对条，仅作视觉参考；管理员评分按钮打开共享评分弹窗。模型私人备注作为表下方整宽条带。
- 对比页：顶部只保留「加入模型」；维度行标注小号权重；窄屏使用纵向模型总览 + 分组维度。
- 工作台：仅管理员；按覆盖率升序列出全部模型，展示综合分、名次、已评分维度与覆盖率。每行提供「添加/编辑评分」，打开同一个评分弹窗；标题行提供「新增模型」入口。
- 工作台不渲染内联评分表、权重侧栏或第二套预览面板；评分、备注与实时预览全部收敛在弹窗内。
- 工作台顶部提供「维度设置」链接，直接进入设置页的维度分区。

### 2.7 设置页

`/settings` 为独立页面，仅管理员可进入，使用三个分区标签与 `tab` 查询参数：

- **维度**：列出启用维度；可切换显示已归档。每行展示名称、说明、权重与状态；支持新增、编辑、归档、恢复与永久删除。新增维度默认权重 0，不改变现有排行，并标记「不参与」；需先编辑权重才进入评分弹窗。权重合计实时显示。删除维度会级联删除该维度评分，必须二次确认。
- **模型**：列出模型、厂商、slug、评分数量与完整度；支持新增、编辑档案、删除。模型档案不包含评分字段；评分从排行、详情或工作台弹窗录入。排行、工作台与设置页共用同一个新增模型表单。slug 由名称生成；纯中文名生成空串时留空并要求手填，不自动拼出空 slug。删除模型会级联删除全部评分，必须二次确认。
- **数据**：展示维度、模型、评分数量；提供完整 JSON 导出，仅管理员可获取。
- 各分区空态直接给出对应创建入口；归档项不提供编辑，只提供恢复与删除。
- 设置页不是排行页的抽屉或标签，不与核心榜单共享首屏。

### 2.8 评分弹窗

- 原生 `<dialog>`，宽度 min(920px, calc(100vw - 32px))，最大高度 90vh；顶部标题、模型厂商与维度数量。
- 摘要条：综合分、排名、覆盖率（暂定标记）、已评分维度；随输入实时更新。
- 主体：所有启用且权重 > 0 的维度逐行展示名称、权重、非负评分输入与备注开关。备注展开为少量文本域，记录测试条件与判断依据。
- 底部：非负提示、保存状态、取消与保存。无改动或校验失败时保存禁用。
- 评分数值不设上限，仅接受有限且不小于 0 的数；步长 0.1，统一保留一位小数。空值表示未评分，保存时删除该维度评分。备注为空时删除该维度备注。
- 预览使用与后端一致的加权计算；只影响显示，不写入服务端。
- 保存按改动差异提交 PUT/DELETE；成功后重取当前页数据并 toast；失败保留弹窗与草稿并显示错误。
- 关闭按钮、ESC 与遮罩点击在存在未保存改动时弹出确认；取消确认保留弹窗，确认后丢弃。
- 存在未保存改动时，站内路由注册 useBlocker，刷新/关闭标签页注册 beforeunload；不能只保护关闭按钮。
- 焦点打开后落在首个评分输入；关闭后返回触发按钮。移动端弹窗内部滚动，底部操作固定可见。
- 排行、详情、工作台三处共用同一个组件与同一套状态计算，不复制评分表单。

### 2.9 响应式策略

- ≥1180px：完整 12 栏，排行表全宽，维度列全部显示；维度总宽超过内容宽度时，表格容器内部横向滚动，页面本身不溢出。
- 760–1179px：刊头统计行横排；排行表保留全部维度，允许表内横向滚动但不得造成页面级溢出。
- <760px：排行仅保留综合排名、模型、综合分、覆盖率、操作；隐藏维度列；模型名可换行；表头仍可点击排序。
- 不设维度数量硬上限；新增维度默认权重 0，设置页标记「不参与」，需先设权重才进入评分弹窗。
- 设置页行在窄屏切换为「索引 / 名称 → 权重 / 状态 / 操作」的两行网格；操作图标保持可见。
- 工作台行在窄屏切换为「模型 + 分数」与「覆盖率 + 评分入口」两行。
- 详情与对比纵向堆叠；对比切换为分组维度。
- 桌面表行图标 30–32px；移动表行图标 34px，移动主按钮 44px；不低于 WCAG 2.2 AA 的 24px。密集表格不套用 HIG 44pt 行内图标，以保留一屏信息量。

### 2.10 文案与反馈

- 用户可见文案全部中文；品牌名、模型名、厂商保留原文。
- 不写功能解释、上手引导、占位标签或「示例数据」。
- 按钮使用明确动作：保存评分、新增维度、新增模型、导出 JSON、移出对比。
- 破坏性操作使用自定义确认框，说明影响对象与是否可恢复。
- 保存成功、API 错误、验证失败通过内联状态或 aria-live 提示。

## 3. 核心架构

### 3.1 技术栈

- 后端：Go 1.27，net/http + ServeMux 方法路由，log/slog，标准库为主。
- 数据库：SQLite，纯 Go 驱动 modernc.org/sqlite，保持 CGO_ENABLED=0。
- 认证：bcrypt 密码哈希 + HMAC-SHA256 签名 Cookie。
- 前端：React 19 + TypeScript + Vite + React Router；CSS Modules + 全局 CSS 变量。
- 图形：内联 SVG 图标与 CSS 数据条；不引入图表库。
- 部署：多阶段镜像、Docker Compose、GitHub Actions 推送到 GHCR。

### 3.2 数据模型

只保留三张业务表：

- dimensions：名称、说明、weight INTEGER NOT NULL CHECK (weight BETWEEN 0 AND 100)、归档时间、时间戳。
- models：不可变 slug、名称、厂商、私人备注、时间戳。
- scores：model_id / dimension_id NOT NULL，value REAL NOT NULL CHECK (value >= 0)，私人评分备注；模型 × 维度唯一，删除模型或维度时级联。

不变式：

- 维度名称不区分大小写唯一；模型 slug 不区分大小写唯一。
- 全局只有这一套维度权重；新增维度仅增加一个权重字段，不复制出第二套表单。
- 权重 0 合法但不参与排行；所有启用维度权重均为 0 时，排行显示「尚未设置权重」空状态，而不是伪造分数。
- 评分只要求非负有限数，不设 10 分上限；综合分可以超过 10。
- 归档只从公开读取与计算中移除，数据保留且可恢复；永久删除才级联。
- 迁移只建表、不插入任何业务数据。

### 3.3 计分与排名

对启用维度中权重 > 0 的维度：

- 综合分 = 已评分维度的归一化加权平均：W = Σ(weight of scored dimensions)，Σ((weight / W) × score)；先归一权重再乘分数，避免有限极大值相乘溢出。
- 覆盖率 = 已评分维度权重之和 / 所有启用且权重大于 0 的维度权重之和
- 覆盖率 < 80% 标记「暂定」；显示向下截断到一位小数，79.9% 不得显示成 80%。
- 未评分模型无综合分与名次，任何视图排序下都排在已评分模型之后
- 单维度评分不设上限；综合分是加权平均，可超过 10
- 官方排序：综合分降序、覆盖率降序、名称升序
- 排行不落库，每次请求由纯函数计算；列排序是前端视图层行为，不改变官方排名
- 评分弹窗的实时摘要复用同一纯函数的前端镜像，保存后以服务端响应为准

### 3.4 API 面

统一前缀 /api，JSON；错误信封为 {error:{code,message,fields?}}。

| 领域 | 端点 |
|---|---|
| 会话 | GET /api/bootstrap、POST /api/auth/login、POST /api/auth/logout |
| 排行 | GET /api/rankings |
| 维度 | GET/POST /api/dimensions、PATCH/DELETE /api/dimensions/{id}、归档与恢复动作 |
| 模型 | GET/POST /api/models、GET/PATCH/DELETE /api/models/{slug} |
| 评分 | PUT/DELETE /api/models/{slug}/scores/{dimensionId} |
| 导出 | GET /api/export（仅管理员） |
| 健康 | GET /api/health |

- 没有 /api/profiles；排行不接收 profile 查询参数。
- 维度响应包含 weight；排行响应包含启用维度的 weight、totalWeight、updatedAt 与全部启用模型。
- totalWeight=0 时固定返回全部启用模型，score/rank 为 null、coverage=0，前端据此区分「无模型」与「无权重」。
- updatedAt 取模型与评分的最大 updated_at；无数据时为 null，刊头不伪造时间。
- 管理员打开评分弹窗时使用 GET /api/models/{slug} 获取评分与评分备注；匿名响应不得包含这些字段键。模型创建与编辑复用同一管理员端点，创建表单不接收评分。
- 公共响应剔除模型私人备注和评分备注；管理员响应保留。
- 评分写入校验 value 为有限且不小于 0 的数，统一保留一位小数；负数、NaN 与 Infinity 返回字段错误，不设上限。
- 归档数据仅 includeArchived=1 且已认证时返回。
- 评分与删除在事务中完成。
- 列排序与评分弹窗都在浏览器端完成；URL 仅保存视图状态，不参与服务端查询。
- 不新增「评分工作台」专用端点；工作台读取 rankings。

### 3.5 认证与安全

- 密码只以 bcrypt 哈希存在环境变量；启动时校验配置，不提供默认密码。
- 会话为 HttpOnly、SameSite=Lax、可配置 Secure 的签名 Cookie，有效期 24 小时。
- 登录失败按 IP 限速；默认取 RemoteAddr，TRUST_PROXY=true 时才读取反代写入的 X-Forwarded-For / X-Real-IP。
- 写请求校验 Origin 的 host 与 r.Host（忽略 scheme）；要求反代保留 Host，依赖 SameSite + Origin 双约束。
- 生产由反向代理终止 TLS；服务仅绑定本机回环映射；反代须运行在宿主机网络，或在部署文档中明确容器网络方案。
- 设置基础安全响应头、请求体上限、服务器超时与优雅关闭。
- 评分弹窗不缓存评分草稿到本地存储；关闭后即丢弃。

### 3.6 构建与部署

- Vite 构建产物由 Go 嵌入；一个进程提供 API、静态资源与 SPA 回退。
- 本地流程：前端 build → Go 测试/构建 → 启动单一进程。
- CI：前端安装/typecheck/build、Go 测试、镜像构建；推送主分支与版本标签时推送到 GHCR。
- Compose 默认拉取镜像，绑定 127.0.0.1:8080，SQLite 使用命名卷；反代与容器共享宿主网络并保留 Host。
- .gitignore 使用 web/dist/* 且保留 !web/dist/.gitkeep；fresh clone 未构建时仍可通过 go:embed 编译。
- 本机无 Docker，镜像真实构建与 Compose 运行由 CI/VPS 验证；本地只验证配置与构建前置。

## 5. 架构决策

| 决策项 | 选择 | 理由 | 未采用 |
|---|---|---|---|
| 权重模型 | 维度直接持有唯一权重 | 直接满足单表单要求，删除方案层与选择器 | profiles + profile_weights |
| 设置页 | 独立 /settings，三分区 | 低频管理事务不占排行首屏；维度增减有确定入口 | 排行内抽屉、管理标签混入工作台 |
| 新增模型入口 | 排行、工作台、设置页复用模型弹窗 | 创建模型不再只藏在设置页；共享表单避免两套字段 | 排行内联新建、独立新建页 |
| 评分上限 | 不设上限，只要求非负有限数；权重先归一化再乘分数 | 按用户要求保留 Top 模型分差，避免极大值相乘溢出 | 固定 0–10、分段封顶、人为 1000 上限 |
| 详情条刻度 | 按当前维度最高分（下限 10）归一 | 无固定上限时仍能扫读相对位置，且不参与计算 | 固定 10 分条、取消所有条 |
| 评分入口 | 共享评分弹窗，排行/详情/工作台复用；有改动时 useBlocker + beforeunload | 一个表单、一个校验与预览实现；防止返回/刷新丢草稿 | 只保护关闭按钮、内联评分表 |
| 工作台职责 | 覆盖率总览 + 打开弹窗 | 保留评分作业视口，同时不复制表单 | 三栏内联评分表 |
| 排行管理员操作 | 行末图标按钮 | 从看到差距到修改评分的最短路径；不改路由 | 跳到独立页面再选择模型 |
| 列排序 | 表头即按钮，客户端排序 | 当前数据全量返回，排序无需请求 | 排序下拉、服务端 sort 参数 |
| 官方排名 | 排序后仍保留加权名次 | 榜单排序是查看方式，不改变加权排名事实 | 按当前排序列重编名次 |
| 空值顺序 | 未评分行始终置底，空维度值也置底 | 缺失评分不因方向切换跳到顶部 | 随方向翻转、按覆盖率 0 排到顶部 |
| 覆盖率阈值 | 低于 80% 标「暂定」，显示向下截断一位小数 | 覆盖率是可信度的直接提示；显示与阈值使用同一精度 | 四舍五入到整数、删除提示 |
| 维度数量 | 不设硬上限，表格容器内部横向滚动 | 保留可增减维度，不因列数破坏页面 | 固定 8 个上限、压缩列宽 |
| 零权重维度 | 不进评分弹窗，设置页标「不参与」 | 避免把不参与计算的分数混入摘要；先设权重再评分 | 允许评分但不计数、默认非零权重 |
| 权重表达 | 维度列下微型数字 + 权重合计 | 保留解释力，同时把版面让给排行内容 | 大侧栏、权重条形图 |
| 视觉密度 | 降低刊头字号、增大行高与间距 | 减少首屏压迫感与连续阅读压力 | 继续放大标题、压缩表格 |
| 品牌图标 | 原色圆形标识，仅页头与 favicon | 保留用户资产识别度，不污染数据区 | 重新着色、滤镜 |
| SQLite 驱动 | modernc.org/sqlite | 纯 Go，免 CGO，符合单二进制 | mattn/go-sqlite3 |
| 评分持久化 | 不落库排名 | 权重修改后即时生效，无重算任务 | 冗余排名表 |
| 会话 | HMAC 签名 Cookie | 单管理员无需会话表 | 服务端 Session 表 |
| 图表 | 无图表库，数据条用 CSS/SVG | 数据形态不需要坐标系 | Recharts、ECharts |
| 部署 | 单 app 容器 + 外部反代 | 资源占用低，TLS 交给 VPS | 内置 Caddy/Nginx |

### 9.2 手工验收路径

1. 删除测试数据库，设置必需环境变量；页面显示空状态，无种子内容。
2. 登录；在设置页新增至少 3 个维度并设置权重，其中验证一个权重 0 的维度不参与排行；归档并恢复一个维度。

5. 在详情页与工作台打开同一评分弹窗，确认字段、预览与保存行为一致；工作台不存在内联评分表；详情页的相对条随该维度最高分归一，页面不出现「/10」固定刻度。
6. 点击「综合分」「覆盖率」「模型」「维度名」验证升降序；未评分行始终置底，维度空值置底；排序后 URL 可刷新复现；官方综合排名保持不变。
7. 构造覆盖率 79.9%，确认显示 79.9% 且带「暂定」；80.0% 时不带；删除或归档维度后排行与覆盖率同步。
8. 以未登录与已登录分别请求 rankings：totalWeight=0 时返回全部模型且 score/rank 为 null；updatedAt 与最大更新时间一致。
9. 匿名刷新：无管理入口、无法写、无私人备注；排行与详情不出现评分按钮。
