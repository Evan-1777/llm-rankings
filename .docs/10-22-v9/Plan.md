# Plan：详情显示口径修正与评审遗留收口

**状态**：DONE（2026-10-22）  
**日期**：2026-10-22  
**版本**：v1.0  
**上游**：用户截图与两项显示缺陷、2026-10-22 只读评审报告（10-22-v8，92/100）

## 1. 背景与目标

用户截图暴露了详情页的两处显示矛盾：百分比模式下，维度排名末位显示 100%，但右侧相对条仍按分值占最高分的比例填充，出现“倒数第一却未满格”；分值色块底部的 2px 横线按整块内边距铺满，比数字本身更宽，读起来像未对齐的填充。

同时，上一轮只读评审提出 6 项问题，集中在该轮新增的工作台快捷编辑与评分写入路径。本轮按工作流要求逐条核对代码，批判性吸收确属实际风险的项，并修复残留。

目标：

- 详情页百分比模式下，相对条与“差距”列使用同一分差百分比口径；最低分 100% 对应满格，最高分 1% 对应近零。
- 分值色块的下划线只覆盖分值文字，不再跨越左右内边距。
- 修复工作台“完成编辑”的提交歧义、保存中仍可离开且确认文案失真、保存结束后在新页面弹出提示的问题。
- 合并 `UpsertScore` 的重复 INSERT；把“未评分参与排序”的键判定收口到一处。
- 消除 Project.md 中移动端表格规则与工作台桌面限定的并存矛盾；让 TASK-006 的“保存中禁用操作”有明确范围与验收记录。
- 自动化测试、桌面浏览器验收、Project.md 同步、归档与提交完整走通。

## 2. 批判性吸收（评审报告 10-22-v8）

| 评审项 | 处理 | 理由与落点 |
|---|---|---|
| 1. “完成编辑”实际执行“放弃并退出” | 采纳（评审首选方案） | 开关保持固定文案“快捷编辑”，继续用 `aria-pressed` 表示状态；不引入“完成=提交”的第二语义。点击已按下的开关仍走放弃确认。 |
| 2. 保存中仍可离开、确认文案与真实行为不符、开关无响应 | 采纳 | 保存中禁用模式开关；离开确认区分保存态，明确“已发出的请求会完成、剩余项不再提交”；卸载后停止后续项并禁止 toast/回写。不采纳 AbortController 中止在途请求：请求可能已落库，中止无法回滚，改为完成在途、停止剩余。 |
| 3. `UpsertScore` 复制整条 INSERT | 采纳 | 单条语句 + note 可空参数 + `COALESCE`；保留“省略保留、空串清空、新记录为空”的既有契约与测试。 |
| 4. “未评分参与排序”的键判定写两遍 | 采纳 | 工作台包装只传 `{ keepUnscored: true }`，由 `sortRows` 统一按键收敛；删除包装里的重复判定。 |
| 5. 移动端表格规则与工作台桌面限定并存 | 采纳 | Project.md 的移动端规则限定到排行、详情与对比；工作台明确为桌面矩阵，仅容器横向滚动。 |
| 6. TASK-006 细节未落实但标 DONE | 采纳（部分） | 保持归档任务的历史状态，不改写已完成的 v8 记录；在 v8 Tasks 的 TASK-006 下补一条带日期的复审补记，指向本轮。把“操作”范围明确为底部操作条与模式开关；表头排序是只读视图操作，不纳入禁用。本轮新增验收记录。 |

评审中“做得好、不需要改”的部分（差分保存契约、备注可选契约、站点百分比的权限与零种子、归档成对、提交风格）保持不动。

## 4. 架构与交互决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|---|---|---|---|
| 百分比模式相对条 | 与“差距”列共用 `gapPercentile`，100% = 满格 | 相邻两列必须同口径；末位满格符合“100% = 最低分”的图例 | 按名次等距：并列分被拆成不同长度；始终按 gap：实际分值模式下会与可见分值矛盾 |
| 实际分值模式相对条 | 保持按最高分归一 | 不改变既有已验收行为 | 统一改 gap：会让“8.2 分”旁边出现满格条，语义反转 |
| 分值下划线 | `text-decoration` 2px，跟随文字宽度 | 只改样式，不加 DOM；与文字天然对齐；不依赖 min-width | 统一色块宽度：只对齐色块，不对齐数字；内嵌伪元素：短分值受 min-width 余量影响 |
| 工作台开关文案 | 固定“快捷编辑”，`aria-pressed` 表状态 | 开关语义稳定；避免“完成=提交”的误读 | “退出编辑”：仍是切换文案，未采用评审首选 |
| 保存中离开 | 完成在途请求、停止剩余项；确认文案区分保存态；卸载后停止 UI 回写 | 部分写入已发生，中止不能回滚；提示必须诚实 | AbortController 中止在途请求：服务端可能已提交前几项，界面与库不一致 |
| 保存中禁用范围 | 输入、底部操作、模式开关；表头排序与只读导航不纳入 | 排序不写库；导航由离开确认接管 | 禁用整页：个人规模短保存，过度阻断 |
| 评分 UPSERT | 单语句 + note 两次绑定 + `COALESCE` | 消除双份 SQL 的同步风险；行为不变 | 两条 SQL：后续加列需同步两处 |
| 排序键判定 | 只在 `sortRows` 内按 key 收敛 | 单一事实来源；包装只表达“允许参与” | 包装与内层各判一次：新增键需改两处 |
| 移动端规则 | 排行/详情/对比隐藏维度列；工作台桌面矩阵 | 与“工作台不做移动布局”的既有决策一致 | 给工作台补移动卡片：用户明确不做 |

## 5. 风险清单

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| 百分比模式“条越长=越差”反直觉 | 🟡 中 | 图例已写“1% = 最高分，100% = 最低分”，红色底色与 100% 数字同向；Project 记录口径 |
| `text-decoration` 在 forced-colors/打印下残留 | 🟢 低 | 两个媒体查询显式 `text-decoration: none`；Chrome 验收 |
| 保存态 blocker 的闭包捕获旧 `saving` | 🟡 中 | 依赖数组加入 `saving`；确认框只在进入 blocked 时创建一次 |
| 卸载后仍执行的保存循环回写状态 | 🟡 中 | `aliveRef` 守卫 toast 与状态更新；请求继续是既定语义 |
| SQLite 对同一参数二次绑定/COALESCE 的行为差异 | 🟢 低 | 现有备注保留/清空/新记录测试覆盖；现代 SQLite 支持参数复用 |
| 手工验收无法覆盖保存竞态 | 🟡 中 | 用 CDP 网络延迟暂停保存请求，验证开关禁用与离开文案；记录步骤 |

## 7. Subagent 协同规划

| 阶段 | 上下文依赖 | 并行收益 | 执行主体 | 决策理由 |
|---|---|---|---|---|
| Phase 1 详情显示 | 强（需同时理解 gap 口径、色阶与表格布局） | 无（两个文件，强耦合视觉判断） | 主线 | 隔离会话需重载设计决策，收益不足 |
| Phase 2 工作台语义 | 强（保存循环、路由 blocker、卸载时序） | 无（单文件状态机） | 主线 | 并发修改同一文件风险高 |
| Phase 3 结构收口 | 低（SQL 与纯函数边界清晰） | 低（改动仅十余行） | 主线 | 交代背景的成本高于改动本身 |
| Phase 4 文档 | 中（依赖前三阶段结果） | 低（单一事实来源需顺序改写） | 主线 | 文档需与代码同步，避免快照漂移 |
| Phase 5 验证与提交 | 中（依赖全部变更） | 无（串行验收） | 主线 | 浏览器与提交需单一上下文 |

**协同结论**：本轮不启用 Subagent。改动集中在四五个文件、强依赖会话中已确认的显示口径与保存时序，且存在浏览器验收的串行依赖；委托的背景重载成本高于并行收益。
