## 1. 背景与目标

站点需要一种临时只读收口手段：管理员在设置中开启维护模式后，未登录访客只能看到居中的品牌 Logo 与维护提示，无法浏览排行、详情、对比等页面；管理员仍可通过登录页进入并正常使用。

目标：

- 维护模式为站点级布尔设置，与百分比模式共用单例，所有设备一致。
- 未登录访客访问任意非登录页面时只看到维护页，页面中央为现有品牌 Logo。
- 维护页提供登录入口；登录成功后恢复完整站点。
- 维护期间匿名 API 读写被拒绝，管理员接口不受影响。

## 2. 阶段划分

### Phase 1：设置数据与接口契约

| 项目 | 内容 |
|------|------|
| **输入** | 现有 `display_settings` 单例、显示设置接口与前端显示偏好 |
| **输出** | 追加迁移、存储层读取/写入两个站点开关、接口读写 `maintenanceMode` |
| **验收标准** | 旧库升级后维护模式默认关闭；缺字段写入返回 422；匿名读取可见维护开关；管理员可切换并持久化 |

### Phase 2：后端维护门禁

| 项目 | 内容 |
|------|------|
| **输入** | Phase 1 的存储读取能力、现有认证与中间件链 |
| **输出** | API 维护门禁：匿名访问非豁免接口返回 503；登录、登出、健康检查与公开显示设置保持可用；静态资源与 SPA 外壳不受影响 |
| **验收标准** | 开启后匿名排行/模型/导出均 503；管理员不受影响；关闭后匿名立即恢复；登录接口在维护期间仍可调用 |

### Phase 3：前端维护页与路由拦截

| 项目 | 内容 |
|------|------|
| **输入** | Phase 1 的设置响应、现有会话上下文与路由布局 |
| **输出** | 维护页（居中 Logo + 状态说明 + 登录入口）；全局布局在维护且未登录时只渲染维护页；登录页保持可达 |
| **验收标准** | 匿名用户任意非登录路径只看到维护页；维护页可进入登录；管理员登录后页面正常；登出后立即回到维护页；无内容闪烁 |

### Phase 4：设置入口与验收

| 项目 | 内容 |
|------|------|
| **输入** | Phase 1-3 的实现 |
| **输出** | 设置「显示」分区维护模式开关；Go/前端测试补充；文档与归档 |
| **验收标准** | 开关可点击、失败回滚并提示；测试、类型检查、构建通过；Project.md 与实际一致 |

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 设置载体 | 扩展现有 `display_settings` 单例 | 同为站点级布尔开关，复用已有迁移、接口与前端偏好层，不新增表或接口 | 新建 `site_settings` 表（重复单例与读写链路） |
| 后端门禁位置 | API 中间件 | 在数据出口统一收口，静态资源与 SPA 外壳继续提供，前端才能渲染维护页与登录页 | 只在 SPA 内拦截（匿名仍可直接请求 API）；服务端整站 HTML 替换（需复制前端样式与路由逻辑） |
| 前端判断来源 | 公开显示设置接口 | 单个来源同时驱动设置页与维护拦截；bootstrap 被门禁阻断时仍能获知维护状态 | 塞进 bootstrap（维护期间匿名无法读取，需额外豁免并泄露计数） |
| 维护页呈现 | SPA 页面，不渲染页头 | 页面中央聚焦 Logo 与状态；避免维护期间出现指向不可用页面的导航 | 保留页头（入口全部不可用，产生噪声） |
| 豁免范围 | 健康检查、登录、登出、公开显示设置 | 维持探活、登录入口与前端状态判断；其余读写一律 503 | 全部 API 放行（门禁失效） |

## 4. 风险清单

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 维护开关读取失败导致匿名绕过前端展示 | 🟢 低 | 后端门禁独立于前端，API 数据仍被阻断；维护页只是表现层 |
| 登出时 bootstrap 被门禁阻断，界面残留已登录态 | 🟡 中 | 登出成功后先落本地未登录态，再刷新会话 |
| 设置 PUT 只带一个字段导致另一个开关被重置 | 🟡 中 | 输入要求两个字段齐全，缺失返回 422；前端一次提交两个值 |
| 维护期间已有会话过期 | 🟢 低 | 现有 401 事件将会话置为未登录，路由拦截自然切换到维护页 |
