# Plan：榜单组列去特殊化与列序归位

**状态**：DONE
**日期**：2026-11-12
**版本**：v1.0
**完成日期**：2026-11-12
**回归测试结论**：自动化基线全绿 —— `go test ./...`（64 个测试函数全绿）、`go vet ./...`、`CGO_ENABLED=0 go build ./cmd/server`、`pnpm --dir web test`（71/71）、`pnpm --dir web typecheck`、`pnpm --dir web build`；`gofmt -l cmd internal` 无输出。浏览器在 1440 / 768 / 390 三视口用临时库真实数据验收：榜单列序为前端纪律 → 前端审美 → 工程能力 → 模型直觉 → …，组列无组色圆点与组色左框线，组列排序（aria-sort）与组明细抽屉正常，导出 PNG 列序与榜单一致且无组色标记，页面级无横向溢出。

## 1. 背景与目标

上一轮（`.docs/11-12-v1`）引入维度组：同名维度在榜单合并为一列，组列固定排在未成组维度列之前，并带组色圆点与组色左框线。本轮按用户图片反馈收口两处体验：

- **组列去掉单独样式**：列头不再有组色圆点，分值单元格不再有组色左框线，列头与单元格沿用维度列的结构与类名。
- **列序归位**：榜单不再「先组列、后未成组维度列」，改为按「组内首个维度在维度顺序中的位置」把组列与维度列交织排列；导出图片与榜单同序。

目标：组列在榜单上只是「一列」，除组内维度数与权重合计外不携带额外视觉标记；用户调整维度顺序时，榜单列序与设置页维度顺序一一对应。

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 列序的单一来源 | `boardColumns` 在既有的 `groups`/`ungrouped` 分区之外新增有序的 `columns` 序列（组/维度判别联合） | 榜单与导出消费同一序列；评分弹窗需要「组块 + 未分组块」的分区视图，两个投影由同一函数一次遍历产出，不存在第二处排序逻辑 | 只保留分区、由各消费方自行交织：两处重复排序逻辑易漂移；只保留序列：评分弹窗需重新分组，爆炸半径更大 |
| 组列视觉 | 删除列头组色圆点与单元格组色左框线，组列改用维度列类名（`.dimCol`/`.dimValue`） | 组列结构上与维度列一致，符合「无需单独的样式」 | 保留组色标记：即本轮要消除的特殊样式 |
| 组列小字 | 保留「n 项 · 权重 w」 | 属内容而非样式，指示该列由几个维度构成 | 改为「权重 w」会丢失组的构成信息 |
| 组值展示口径 | 不改：仍按换算分两位小数渲染，不接入百分比模式与色阶 | 本轮范围是列样式与列序；把组值接入色阶/百分比属显示口径变更，需为组引入新的区间与最大值来源，超出图片要求 | 组值改走 `DimensionScore`：需新增组区间/组最大值计算并给组值上底色，属未经要求的功能扩张 |
| 组色用途 | 保留在明细抽屉组内切换、评分弹窗左框线与设置页组色块 | 这些位置的组色承担分组识别职责，与榜单列标记无关 | 全链路删除组色：会破坏评分弹窗与设置页的组识别 |

## 4. 风险清单

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 导出图片与榜单列序漂移 | 🟡 中 | 两者共用 `boardColumns().columns`；纯函数测试锁定交织顺序与坐标不重叠 |
| 移除 `SortButton` 的 `dot` 造成其它调用点破坏 | 🟢 低 | 全仓检索确认 `dot` 仅组列列头使用 |
| 删除 `.groupCol`/`.groupValue` 后移动端列隐藏失效 | 🟢 低 | 组列改用 `.dimCol`，与维度列共用同一隐藏规则；三视口验收 |
| 排序 URL 参数（`group-<组名>`）因列序变化失效 | 🟢 低 | 排序键与解析逻辑不变，仅渲染顺序变化 |

## 6. Subagent 协同规划

对照三维效益模型（任务复杂度、上下文关联度、经济与时间效益）评估本轮委托需求：

| 阶段 | 上下文依赖 | 并行收益 | 执行主体 | 决策理由 |
|------|-----------|---------|----------|----------|
| Phase 1：列序列与榜单渲染 | 强（列序语义、样式类名与既有榜单结构耦合） | 无 | 主线 | 改动集中在一个纯函数与其渲染消费方，隔离会话重载上下文的开销高于改动本身 |
| Phase 2：导出对齐 | 强（依赖 Phase 1 的列序列与样式决策） | 无 | 主线 | 与 Phase 1 串行，且同为小差分 |
| Phase 3：测试与文档 | 中（测试锁定 Phase 1/2 的契约，文档为只读参照） | 低 | 主线 | 测试与文档须反映本会话的判定（组值口径、组色去向），拆给隔离会话反而需重复交代 |

> **协同结论**：本轮为单点收口（一个纯函数 + 两个渲染消费方 + 样式与文档同步），链路短且强依赖会话内决策，全部由主线推进；不派发 Subagent。
