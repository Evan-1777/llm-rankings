## 1. 背景与目标

11-12 九轮交付（维度组、跳过维度与 60% 中位分、榜单组列同构、明细抽屉、PNG 导出、显示口径同步）已归档且自动化基线全绿。审阅报告给出 6 项问题与 88 分。本轮只收口经核实成立、且改动可跨层同构的契约偏差，不重做 11-12 的既有设计。

| # | 目标 | 判定标准 |
|---|------|----------|
| 1 | 「已评分」在三处统计中同义 | 榜单首屏占位计数与加载后统计同值、不跳变；工作台按同一规则统计（含隐藏模型）；三处均与「跳过不计入已评分」的既有口径一致 |
| 2 | 模型行「已评维度数」与综合分口径同源 | 设置页模型行的已评维度数 = 工作台/详情页的 `scoredCount` |
| 3 | JSON 导出覆盖全部评分状态 | 导出载荷含 `skips`，可完整还原综合分与名次 |
| 4 | 抽屉与设置页的交互状态不残留 | 关闭后重开抽屉回到首个维度；行内新建组名不静默丢弃 |
| 5 | 绘制契约与榜单同源 | 导出图的第 1 名标记按名次判定，不按行序 |

非目标：导入功能、评分历史、抽屉键盘漫游、画布文本换行/截断、跳过中位分的前端复算（见第 3 节决策）。

## 2. 审阅报告吸收结论

核实方式：逐条通读代码库现状（`internal/store`、`internal/api`、`web/src`）与 Project.md 既有契约，再判定采纳或驳回。

| 审阅条目 | 处理 | 落地口径与理由 |
|---------|------|---------------|
| 问题 1 前段：`scoredModels` 与榜单统计分裂 | 采纳（方向与审阅相反） | 不把跳过并入「已评分」——那等于宣布只有跳过的模型已完成评分，与工作台补测优先级语义冲突。口径统一为「至少一个有权重、未归档、未跳过的已评分维度」：前端两处统计改按 `scoredCount > 0`，bootstrap 摘要计数同步排除已跳过维度，使占位值与加载后同义 |
| 问题 1 后段：`ScoredDimensions` 未排除已跳过维度 | 采纳 | 模型行已评维度数补 `NOT EXISTS (score_skips)`，与领域层 `ScoredCount` 严格同构（Project.md「跳过不进入已评分维度计数」） |
| 问题 2：JSON 导出遗漏 `score_skips`，注释与实现不符 | 采纳 | 导出补 `skips`（模型 slug + 维度 id）；导出含评分与文字却独缺跳过，无法还原综合分；补后 `AllSkips` 注释「rankings and export」自洽 |
| 问题 3：评分弹窗预览未随草稿复算 `skipMedian` | 驳回 | 前端复算会在公开榜单场景系统性偏差：该弹窗行集来自 `rankings(false)`（不含隐藏模型），而服务端候选集含隐藏模型（Project.md:141、ranking.go 快照模型含隐藏）；打开时刻的静态值才是精确值。11-12-v1 已决策「中位分不由前端实现第二份」，复算需再加「行集完整性」守卫，复杂度不匹配。改为在已知限制中记录该偏差 |
| 问题 4 前段：`DetailDrawer` 跨组残留 `activeId` | 采纳 | 挂载点按目标键控（`key`），切换或重开时重置到首个维度 |
| 问题 4 后段：`role="tab"` 缺键盘漫游 | 采纳（删除式修复） | 该选择器是互斥按钮组而非需方向键的 tablist，去掉 tablist/tab 语义并改用 `aria-pressed`；不为此复制设置页的分区 Tab 机制 |
| 问题 5 前段：导出图按 `index === 0` 判定第 1 名 | 采纳 | 改按 `model.rank === 1`，与榜单 DOM 契约一致；无排名行不再被涂成冠军 |
| 问题 5 后段：长模型名未做列宽裁剪 | 驳回 | 画布文本无回流，正确修法是覆盖模型列与全部列头的统一截断策略（列头为右锚点、向左溢出），只裁一列会引入新的不对称显示策略；当前名称上限远高于真实数据长度，榜单 DOM 用换行而非截断 |
| 问题 6：`DeleteSkip` 未复用 `resolveRatingTarget`、与 DELETE 评分及文档不对称 | 部分驳回 | 审阅引用的 scores.go:79–88 是 `resolveRatingTarget` 本体；`DeleteScore` 同样只校验模型、不校验维度，二者已对称，且与「删除幂等」一致。真实缺陷是 Project.md 把 PUT/DELETE 混写为同一错误码契约，改为分别陈述 |
| 第 4 节：设置页行内新建组失焦静默丢弃 | 采纳 | 失焦时提交非空组名（空则仅收起）；该入口是 Project.md 记录的既有能力，保留而非删除 |
| 第 4 节：`DetailTarget.color` 的 `null` 兜底为不可达分支 | 驳回 | `color` 是 `string \| null` 的既有字段，兜底使其可安全渲染；色块仅在组目标渲染且组色恒为 6 色之一，删除需改类型或加断言，收益为零 |
| 第 4 节：表头空副行占位与单日多轮返工 | 无需动作 | 审阅自身结论为可接受折中；返工属过程观察 |

附带核实：审阅多处行号与实际文件不符（如 `exportImage.ts:69` 并无 `MODEL_WIDTH`、`Rankings.tsx:504` 并非抽屉挂载点），且「工作区无残留」不成立——`web/dist/.gitkeep` 当前处于未提交删除态，而 `web/embed.go` 的 `//go:embed all:dist` 依赖该占位文件保持可编译。

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 「已评分」的唯一口径 | 至少一个「有权重、未归档、未跳过」的已评分维度 | 与 `scoredCount`、bootstrap SQL 同义；与 Project.md「跳过不计入已评分维度计数」一致 | 把跳过并入 `ScoredModels`（等于宣布只有跳过的模型已评分，与工作台补测优先级语义冲突） |
| 统计计算位置 | 前端由已下发的 `scoredCount` 派生，bootstrap 摘要计数按同一规则修正 | 单一数据源；占位值与加载后必须同义，不新增接口字段 | 后端新增 counts 字段（重复下发同一量） |
| 跳过中位分的来源 | 保持服务端唯一下发 | 避免两份 60% 分位实现漂移；行集完整性无法在前端保证 | 前端复算（见第 2 节驳回理由） |
| DELETE 语义 | 保持「仅校验模型 + 幂等」，文档按此收敛 | 与 DELETE 评分一致；客户端只删除自己读到的维度 | 给 DELETE 补维度校验（与幂等契约冲突，且多一次查询） |
| 抽屉选择器语义 | 互斥按钮组 + `aria-pressed` | 删除误导性的 tablist 契约即可合规 | 实现 roving tabindex 与方向键（为一个选择器复制第二份 Tab 机制） |
| 画布长文本 | 维持现状 | 无回流可用，统一截断策略超出本轮范围 | 仅截断模型名（不对称、且引入新显示策略） |

## 4. 阶段划分

### Phase 1：统计口径统一

| 项目 | 内容 |
|------|------|
| **输入** | 模型行维度计数与 bootstrap 摘要计数；榜单与工作台顶部统计 |
| **输出** | 两处服务端计数均排除已跳过维度；前端统计按「至少一个已评分维度」判定 |
| **验收标准** | 同一模型在设置页、工作台与详情的已评维度数一致；带历史分值的 Skip 维度不再计入；榜单首屏占位数与加载后统计数相同（工作台无占位，按同一规则统计）；store 测试覆盖「已评分 + 已跳过」用例 |

### Phase 2：导出备份完整性

| 项目 | 内容 |
|------|------|
| **输入** | 管理员 JSON 导出载荷与跳过记录读取 |
| **输出** | 导出响应含 `skips`（模型 slug + 维度 id） |
| **验收标准** | 导出 JSON 的 `skips` 与库中一致（含隐藏与归档模型的记录）；匿名仍 401；导出后可据此还原综合分；Project.md 接口段与已知限制同步 |

### Phase 3：交互与绘制契约修正

| 项目 | 内容 |
|------|------|
| **输入** | 明细抽屉挂载点与组内选择器；导出图行绘制；设置页维度组列 |
| **输出** | 抽屉每次打开回到首个维度且选择器为合规按钮组；导出图第 1 名标记按名次；行内新建组名收敛为失焦单一提交入口 |
| **验收标准** | 浏览器读回：关闭后重开同一组/另一组均落在首个维度，无 `role="tab"`；导出图中 rank 1 行带冠军标记、无排名行不带；行内新建组名的四态（点击他处提交、回车提交且只发一次请求、空回车不改分组、Escape 取消） |

### Phase 4：验证与文档

| 项目 | 内容 |
|------|------|
| **输入** | 前三阶段改动 |
| **输出** | 自动化基线全绿 + 浏览器验收记录；Project.md 与代码一致 |
| **验收标准** | go test / vet / build、gofmt、web test / typecheck / build 全绿；Project.md 的导出、统计、接口、已知限制与验证段落同步，无过期表述 |

| 项目 | 内容 |
|------|------|

| **验收标准** | 归档目录双文件齐备、根目录无残留；`web/dist/.gitkeep` 未被删除提交；`git status` 干净 |

## 5. 风险与依赖

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 「已评分」口径调整后与其它消费方（对比、详情）不一致 | 低 | 该统计仅榜单与工作台顶部展示；详情用服务端 `scoredCount`，本就同源 |
| 导出新增字段破坏既有消费方 | 低 | 载荷只增字段、`version` 不变；无导入功能，无消费方依赖字段顺序 |
| 行内新建组的提交与取消互相干扰（元素卸载是否派发 focusout 依浏览器而异） | 低 | 提交收敛为失焦单一入口：Enter 主动触发失焦、Escape 先清空 DOM 值再收起，两种浏览器语义下都只提交一次；浏览器验收覆盖三态 |
| 抽屉按目标键控导致每次开合重挂载 | 低 | 目标变化本就整体替换内容；无跨开合的组件内状态需要保留 |
| 浏览器验收依赖本机 Chrome 9222 实例 | 中 | 按 SCOPE 约定连接用户已开启的实例；不可用时向用户说明后再验收 |

## 7. Subagent 协同规划

对照三维效益模型（任务复杂度、上下文关联度、经济与时间效益）评估本阶段委托需求：

| 阶段 | 上下文依赖 | 并行收益 | 执行主体 | 决策理由 |
|------|-----------|---------|----------|----------|
| Phase 1–3 | 强（跨 store / API / 前端三层的小差分，需同时握住新契约与既有口径） | 无（总改动约 40 行、5 个文件，且相互需保持一致） | 主线（交付段接手模型） | 隔离会话重载上下文与读盘开销超过任务本身；委托无法形成实质并行 |
| Phase 4 | 强（验收口径依赖前述全部改动） | 低（浏览器验收为串行操作） | 主线 | 验收结论须与改动同一上下文，避免二次传递失真 |
| Phase 5 | 弱（机械归档与提交） | 低 | 主线 | 归档依赖前序全部产出，串行收尾 |

> **协同结论**：本轮全部保留主线，不派 Subagent。改动总量小、层间需强一致，委托的重载成本高于收益。
