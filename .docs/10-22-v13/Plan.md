## 1. 背景与目标

本轮输入由五部分组成：

- 维护页当前展示「管理员登录」入口，用户要求撤下该入口，登录页仅保留直接 URL。
- 模型需要独立的显示开关：关闭后不进排行榜，只在评分工作台出现，且名称与数字弱化为浅灰。
- 模型需要与维度一致的归档能力：归档项列在模型页下方，可恢复、可永久删除。
- 维度需要「不纳入评分」：数值仍展示，但不计入综合分与覆盖率；开启后可继续开启「填入文字」，用一段中英文皆可的文字代替评分，该维度不参与任何计算。
- 吸收 10-22-v12 审阅报告，修复确有依据的残留问题，并记录不采纳项的理由。

目标：

- 维护页不再出现任何登录入口，管理员直接访问 `/login` 完成登录。
- 模型具备「显示 / 隐藏」与「归档 / 恢复 / 永久删除」两条生命周期；隐藏只影响榜单与对比候选，归档退出全部列表与计算。
- 权重 0 成为「不纳入评分」的唯一事实来源：数值维度在所有展示面可见，综合分、覆盖率与官方名次不受影响。
- 文字维度以单字段自由文本记录，按模型保存，详情页展示、评分弹窗录入，不进入排行与对比表格。
- 审阅报告中的文档结论、门禁断言与 Project.md 结构问题在本轮关闭；不改动百分比显示口径。

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 模型显隐载体 | `models.hidden` 布尔列 | 显隐是模型自身属性，随模型读写，不引入第二张设置表 | 独立设置表（单值也要新表与联表）；复用 `archived_at`（归档与临时隐藏语义不同） |
| 模型归档语义 | `models.archived_at`，与维度归档同构 | 复用已有的归档/恢复/永久删除模式与交互语言 | 新增状态枚举（只为两态增加概念层） |
| 隐藏的作用范围 | 不进公开排行、对比候选与名次计算；工作台与详情直链保留 | 工作台需要继续评分，详情是工作台的自然入口；隐藏不是权限隔离 | 详情一并 404（工作台链接失效，需要额外分支） |
| 不纳入评分的载体 | 沿用权重 0，并让权重 0 维度参与展示 | 单一事实来源，不新增与权重冲突的布尔列；旧数据自然生效 | 新增 `excluded` 列（与权重 0 形成两套「不计分」状态） |
| 文字维度存储 | `dimensions.text_mode` + `dimension_texts` 单字段文本 | 文字与数值评分语义不同，独立表避免污染 `scores`；文字维度权重固定 0 | 复用 `scores.note`（需要伪造数值）；中英双字段（无证据的双语结构，列与编辑行翻倍） |
| 文字维度展示 | 详情页独立区块，评分弹窗录入；不进排行、对比、快捷编辑 | 排行榜是数值表格，长文本会破坏列宽与扫描效率；文字维度的价值在单模型阅读 | 榜单文字列（表格密度与响应式成本高） |
| 隐藏数据的接口 | `GET /api/rankings?includeHidden=1`，仅管理员 | 复用 `includeArchived` 的既有模式，公开响应保持干净 | 前端二次请求逐模型详情（N 次请求，契约更碎） |
| 维护页登录 | 删除可见入口，保留 `/login` 直链 | 直接满足「不展示登录入口」，不改变认证链路 | 隐藏但保留按钮（与要求冲突） |
| 门禁查询顺序 | 认证判定前置，再读显示设置 | 管理员请求不再触发一次多余查询，改动一行 | 重构路由表与豁免清单（收益低于改路由声明的扰动） |
| 测试记录组织 | Project.md 按归档目录分组，上一增量只留最近一轮 | 让历史记录有归属，避免同日记录平铺与长句；归档目录本身即变更记录 | 再维护一份汇总（同一事实的第二份副本） |

第二轮审阅（88 分）的处置：

| 条目 | 判定 | 处置 |
|------|------|------|
| 隐藏模型详情的评分弹窗预览链断裂 | 采纳 | 评分弹窗在预览前把当前模型合并进行集，不依赖公开排行是否包含它；补隐藏模型预览验收 |
| 「不纳入评分」与「填入文字」的取消路径未定义 | 采纳 | 取消「不纳入评分」时一并关闭文字模式；关闭文字后保持不纳入，权重仍为 0，不伪造权重 |

| 隐藏行排序留了二选一 | 采纳 | 定为隐藏行统一排在可见行之后，计算、预览与视图排序一致 |
| 隐藏模型详情「对比」入口落到空对比页 | 采纳 | 隐藏模型不展示对比入口，下一步导航仍按公开排行判断 |
| 历史头部修正只覆盖两个归档 | 采纳 | 范围写死为报告点名的 v11/v12 两处，v6–v10 同类缺失登记为历史例外，不批量回填 |
| 新增 `--ink-4` 触碰对比度且多余 | 采纳 | 复用 `--ink-3`（约 4.97:1），不新增令牌；弱化不牺牲 4.5:1 可读性 |
| 变更记录与归档目录重复 | 采纳 | 删除拟新增的变更记录，归档目录与测试记录分组承担历史索引 |
| Project.md 重组与归档修正压在最后一个 Task | 采纳 | 拆为 Project.md 重组、历史归档修正、归档提交三个 Task，缩小回滚边界 |

## 6. Phase 依赖关系

```
Phase 1 ──→ Phase 2 ──→ Phase 3 ──→ Phase 4 ──→ Phase 5
```

Phase 1 定型存储与接口；Phase 2 固化排名与门禁口径；Phase 3、4 分别覆盖管理面与展示面，但共享同一契约，按主线串行执行；Phase 5 在全量验证后统一改文档、归档与提交。

## 7. Subagent 协同规划

| 阶段 | 上下文依赖 | 并行收益 | 执行主体 | 决策理由 |
|------|-----------|---------|----------|----------|
| Phase 1：数据与契约 | 强（跨迁移、存储与接口） | 无 | 主线 | 契约一次定型，拆分会产生重复读盘与接口漂移 |
| Phase 2：排名与门禁 | 强（依赖 Phase 1 与既有排名契约） | 无 | 主线 | 名次一致性需要端到端推演，主线处理更稳 |
| Phase 3：设置与维护页 | 强（依赖前端状态与既有交互） | 低 | 主线 | 改动集中在同一设置页与一个页面，拆分成本高于收益 |
| Phase 4：展示与编辑 | 中（接口已定型） | 低 | 主线 | 与 Phase 3 共享组件与样式，串行修改避免冲突 |
| Phase 5：验证与文档 | 中（代码已定型） | 低 | 主线 | 测试记录归组需要对照归档与代码事实，主线掌握全部上下文 |

> **协同结论**：本轮是跨层连续变更，契约、排名口径与展示面强相关，无法切成自包含的并行块；全部由主线执行，不派发 Subagent。
