## 1. 背景与目标

模型厂商目前只能手填；排行维度列只有数字，对比仅将所选模型中的最高分标红。新增已有厂商建议，并以现有墨色色阶呈现同维度得分差异，提供可持久化的个人显示开关。

范围限定在前端：复用已加载的模型列表、现有弹窗与表单；不新增依赖、厂商实体、接口、数据库迁移或评分规则。厂商仍为自由文本，不提供厂商管理、别名合并或批量重命名。评分强调仅作用于只读维度得分，不扩展至综合分、覆盖率、权重、评分输入与预览。

## 3. 架构决策

### 厂商来源与输入方式

候选由父页面现有完整模型列表派生，去除首尾空白、过滤空值、精确去重、按中文 locale 稳定排序。保留大小写与内部空格，不自行将不同名称合并。编辑初始厂商照常回填。选择仅改变当前字段；可随后修改、清空或输入新厂商。创建成功后沿用父页重载，新厂商即可复用；删除最后一个使用某厂商的模型后，该建议消失。

采用原生 select，复用现有 Field 与 select 样式，列出“不填写”、已有厂商及“新厂商…”；选新厂商后展开文本输入，仍可通过下拉返回已有项或清空。无候选时直接显示文本输入，避免空下拉。编辑时保证当前非空厂商包含在选项中。选择不触发表单提交、不改变其他字段。候选是父页面最近加载的快照，不额外请求、不伪造默认厂商；初始加载或请求失败时仍能手填。规划原型中 datalist 的键盘试验未完成候选选择且 Enter 提交了表单，因此改用有明确选项的原生 select，不构建自定义 combobox。

### 得分映射与跨页一致性

每个启用维度独立提取全榜全部模型的已评分有限非负数，计算 min/max。数值位置 t = (value − min) / (max − min)，映射为墨色 6%–18% 的背景透明度：浅为低、深为高；下限保证低分端不接近纸白而失去可辨差异。始终保留墨黑数字及现有一位小数格式。评分不设上限，因此不采用 0–10 固定阈值，也不复用详情相对条的下限 10 标尺。

同一全榜快照下，排行、详情、对比使用相同维度范围；对比选项增减及视图排序不改变同一个分数的色阶。只改变显示，不写入数据、不参与综合分、覆盖率或排名。每个维度范围只计算一次，不在单元格内重新扫描；详情页的 memo 放在 loading/404/error 早返回之前，以 `data?.rankings.models` 为依赖，避免 Hooks 顺序问题。

缺失值继续显示破折号、不着色；真实 0 正常参与。无有效数、仅一个数或所有数相等时不着色，避免制造高低差。极大有限分数映射必须保持有限且位于范围内。相同值同色，重排维度不影响结果。

对比页旧的最高分红字由统一墨色背景替代，移除桌面与移动端残留样式、`maxByDimension` 与旧最高值分支，避免两套视觉规则冲突。明确取舍：开关关闭即关闭全部维度强调（新增背景与对比旧最高红字一并消失），不维护两套强调规则。详情已有相对条保留，其长度含义与算法不变，开关仅控制新增背景。排行移动端继续隐藏维度列，不为强调重新展开宽表。

### 个人显示偏好

采用单一布尔偏好“维度得分强调”，默认开启，切换立即生效；使用浏览器 localStorage 保存，限当前浏览器与站点，不写服务器、不随 JSON 数据导出、不在退出登录时清除。未保存值或无效值采用默认开启；读取失败仍正常展示，写入失败保留当前会话偏好并用现有反馈通道说明未能持久化。存储读写拆成必须存在的纯 TS 模块，接口接收 `Storage` 或读写函数，React 上下文只负责接线；Node 原生测试注入假存储，不导入 `.tsx`。

偏好放在现有管理员设置页，新增“显示”分区（`/settings?tab=display`），复用现有设置 tabs，仍由 `RequireAdmin` 保护。不新增公开设置路由，不调整 Header 入口，不为一个布尔值抽共享设置导航或改路由守卫。访客按默认开启查看；若未来需要访客自控，另立需求再评估。

偏好状态独立于登录状态，由应用级单一上下文提供，避免三个页面各读各存。只增加一个开关，不增设强度、阈值、配色、图案或同步选项。不要求跨设备或多个已打开标签页实时同步。

## 4. 前端设计

沿用项目明确约定：Apple HIG 用于操作、键盘和焦点基准，视觉服从瑞士编辑式规范。纸白 #F2EFE6、墨黑 #14130F、信号红 #B92A20；零圆角、1px 分隔线、无阴影、无渐变、现有字体栈。此次不加载 Fluent 或 Material 3，不引入 UI 组件库。

P0 为排行/详情/对比数据，P1 为原有模型模态，P2 为管理员设置显示分区。Layer 0 纸白画布，Layer 1 表格与直线分隔，Layer 2 沿用页头，Layer 3 沿用模型弹窗和 rgba(20,19,15,.46) 遮罩。既有平面规范优先于通用技能的材质建议。

色阶只覆盖得分数字周围的矩形区域，预留内边距，不铺满整行；墨黑字不随强度变淡、不反白，正文对比度不低于 4.5:1。数字对齐及表格密度保持；排行 hover 不覆盖色阶；长数字允许容器内滚动或扩展，禁止裁掉数值。不制作色阶图例：列头、精确数字与相对深浅已足够，避免为可选构件增加界面噪声。强制颜色/打印时不依赖背景，数字始终可读。

原型仅包含受影响的排行维度列、模型表单、对比与详情得分、显示分区，省略无关管理功能。已有厂商选择、弹窗开关、页面切换、设置切换和表单反馈可操作；不调用服务端、不更改真实数据。

规划验收：桌面 1436px 色阶可读、无页面横向溢出；原生 select 实际选择 OpenAI、创建反馈与焦点恢复通过；390px 下排行、对比卡片、详情和管理员显示分区无页面横向溢出，新厂商输入展开并获得焦点；开关清除/恢复全部新增背景通过，最终原型浏览器无脚本错误。浏览器运行于独立空白文档，localStorage 持久化与业务权限回归仍由交付阶段在实际站点验收；未将原型验收视为业务功能通过。

## 5. 风险与控制

| 风险 | 控制与验证 |
|---|---|
| 无上限分数被误当成十分制 | 只做同维度全榜相对映射；覆盖 0、12.5、极大有限值 |
| 小差异在 min/max 下铺满色阶 | 使用 6%–18% 的弱背景，保留精确数字；不引入绝对质量或跨维度比较的暗示 |
| 对比与排行同分不同色 | 对比按全榜范围取色，不按已选子集重新缩放 |
| 显示分区被误当作公开设置 | 不新增公开路由；显示分区仍在 RequireAdmin 内，匿名访问 `/settings?tab=display` 回到登录 |
| 厂商自由输入与已有项切换丢失状态 | 原生选择控件只更新厂商；新厂商输入与清空有明确路径；编辑初值及保存后候选回流验证 |
| 存储不可用 | 状态仍可切换；写失败反馈只影响偏好持久化，不阻断排行 |

## 6. 依赖与协同

Phase 1 与 Phase 2 业务独立，但都触及排行和设置；同一写入者串行执行可避免冲突。Phase 3 依赖前两阶段完成。

规划段已委托一个只读 explore 子任务独立追踪厂商链路；主线同时追踪评分和权限，获得实际并行收益。任务复杂度中等，子目标自包含且与评分推演关联低，重载成本可接受。交付段改动集中、共享页面较多，额外 executor 会重复加载上下文且产生同文件写冲突，因此三个 Phase 均由接手主线执行，不再拆并行写入。
