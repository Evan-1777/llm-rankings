# Plan：模型评语与 10-22-v13 审阅残留收口

**状态**：DONE

**完成日期**：2026-10-23
**回归结论**：Go 测试与构建、前端测试/类型检查/构建通过；浏览器验收覆盖 1440 与 390，评语可见性、隐藏模型可达面、覆盖率弱化、维度默认权重与强度基准均通过。

## 1. 背景与目标

本轮输入：模型详情页需要展示管理员设置的「模型评语」；评语可设置公开与否；评语结尾展示评语时间，用于提示时效性；评语、公开开关与评语时间均在设置页的单模型弹窗内设置；评语与私人备注互不覆盖、互不混淆。另按 Review 流程吸收 `10-22-v13` 审阅报告，收口上一轮遗留的实现问题。

目标：

- 模型档案新增独立的评语字段、公开开关与评语日期，三者与现有私人备注分列存储。
- 模型详情页底部新增「模型评语」区块：公开评语对所有访客展示，未公开评语仅管理员可见并带标记；评语正文之后紧跟评语日期。
- 设置页单模型编辑弹窗可编辑评语、勾选公开、选择评语日期；新建模型沿用现有档案字段，不增加创建期空评语。
- 评语不进入排行、对比、工作台、评分弹窗与任何计算；导出包含评语，保证备份可还原全部档案信息。
- 收口审阅确认的四项实现问题：隐藏模型的匿名可达面、工作台隐藏行覆盖率弱化、新建维度默认权重、隐藏模型详情的强度基准。

范围外：评语历史与多版本、富文本或 Markdown、按语言分栏、系统自动写入评语时间、评语在列表页的摘要展示、公开评语的评论或互动能力；不补做 v13 的 TDD 仪式，不改动排名、权重与色阶口径。

### 1.1 审阅报告吸收

| 审阅问题 | 判定 | 处理 |
|---|---|---|
| 隐藏模型的匿名可达面大于「只在评分工作台出现」 | 采纳 | 匿名模型列表过滤隐藏项，隐藏模型详情对未认证请求返回 404；管理员不受影响。推翻 v13「隐藏不是权限隔离」的记录，同步修正 Project.md |
| 工作台隐藏行的覆盖率数字与进度条未弱化 | 采纳 | 覆盖率组件增加弱化态，隐藏行传入；百分比与进度条统一为 `--ink-3`，暂定标记保留警示色 |
| 新建维度弹窗默认权重 0 与校验冲突，取消「不纳入」后权重仍为 0 | 采纳 | 新建默认权重改为 50；取消「不纳入」时权重非正数则回落 50 |
| 隐藏模型详情的综合强度基准缺少模型自身，出现 99.9% 或「—」 | 采纳 | 详情展示范围合并当前模型（已在排行中则不重复），综合强度、维度强度与相对条共用同一范围 |
| TASK-016 的失败前置验收没有记录 | 部分采纳 | 不补失败演示；本轮测试验收改为可观察断言清单（断言文件、字段与状态），执行结果写入测试记录 |

未发现需要削减的过度设计；审阅提出的「库级约束」「新增设置表」等方向本轮不引入。

## 2. 阶段划分

### Phase 1：数据与接口契约

| 项目 | 内容 |
|------|------|
| **输入** | 现有 `models` 表、迁移机制、模型列表/详情/更新接口与 JSON 导出 |
| **输出** | 追加迁移：评语正文、公开标记、评语日期三列；存储层模型结构与评语写入；模型列表、详情、更新与导出契约中的评语字段与可见性规则 |
| **验收标准** | 旧库升级后评语为空、未公开、无日期；评语可写入并在列表、详情回读；未公开评语不出现在任何匿名响应；评语长度与日期格式校验按字段返回 422；导出包含三字段 |

### Phase 2：设置弹窗录入

| 项目 | 内容 |
|------|------|
| **输入** | Phase 1 的接口字段与前端类型 |
| **输出** | 模型编辑弹窗中的评语文本域、公开勾选与评语日期输入；前端类型与请求载荷同步 |
| **验收标准** | 编辑已有模型时回填三项；保存后重开弹窗保持；评语留空时详情页不出现区块；日期留空合法；新建模型不出现评语字段 |

### Phase 3：详情页展示

| 项目 | 内容 |
|------|------|

| **验收标准** | 公开评语在匿名与管理员视图一致显示；未公开评语仅管理员可见且标记正确；无评语时区块不渲染；私人备注内容与可见性不变；1440 与 390 无横向溢出 |

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 评语载体 | `models` 新增 `commentary` 文本列 | 评语是模型档案属性，随模型读写与导出，不新增关联表 | 复用 `notes`（私人备注公开化会破坏既有隐私契约）；独立评语表（单值也要联表与级联） |
| 公开控制 | `commentary_public` 布尔列，默认 0 | 默认不公开与私人备注的隐私取向一致，公开需显式开启 | 默认公开（新评语在管理员确认前即对外可见） |
| 时间载体 | `commentary_at` 文本日期，格式 `YYYY-MM-DD`，默认空 | 日期由管理员手填，用于表达评语时效；只存日历日期，避免时区换算把日期挪一天 | 系统时间戳（无法表达「评语写于哪一天」的编辑意图）；带时刻的 RFC3339（展示与输入都多一层时区噪声） |
| 可见性口径 | 详情：公开评语对所有人，未公开评语仅管理员；列表：仅管理员携带；导出：始终包含 | 与私人备注的现有隐私分层同构，匿名响应保持干净 | 未公开评语对所有人生成但由前端隐藏（内容已泄漏到网络层） |
| 展示位置 | 详情页最底部，私人备注之上 | 评语是公开阅读内容，私人备注是管理员附注；先公开后私有的层级符合阅读顺序 | 置于维度表之上（打断评分表的阅读主线）；与私人备注合并为一个区块（混淆两种可见性） |
| 时间展示 | 评语正文结尾的内联日期，等宽小号、弱化色 | 直接满足「结尾展示评语时间」，不新增标题或说明文案 | 独立时间行（多一行噪声，弱化「结尾」语义） |
| 创建期字段 | 评语只在编辑弹窗出现 | 创建只承担档案字段，评语通常在模型有内容后补写；避免创建接口参数膨胀 | 创建表单同显评语（三字段在创建期为空的常态，且扩大创建契约） |
| 隐藏的公开可达面 | 匿名列表过滤，匿名详情 404；管理员保留列表、详情与工作台 | 与「关闭后只在评分工作台出现」一致；详情直链只在登录态可用 | 维持 v13 的公开直链（匿名可读全量评分、文字与评语，与需求冲突） |
| 详情强度基准 | 展示范围合并当前模型，已在排行中则不重复 | 隐藏模型的百分比、色阶与相对条和可见模型同基准；与评分弹窗预览的合并思路同构 | 维持公开排行基准（隐藏模型出现 99.9% 上限或「—」） |

## 4. 风险清单

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 未公开评语经列表、详情或导出意外泄漏给匿名访客 | 🔴 高 | 服务端按管理员身份裁剪字段；回归测试对匿名响应断言字段缺失 |
| 收紧隐藏模型的匿名可达面后，既有外部直链失效 | 🟢 低 | 只影响匿名直链；管理员工作台、设置页与详情入口不变；Project.md 记录语义变化 |
| 旧库升级后默认值不符合预期，出现把空评语当公开的展示 | 🟡 中 | 迁移为三列提供空串/0 默认值；存储测试断言新建与升级的默认状态 |
| 日期被当作系统时间做时区换算，展示日期与填写日期不一致 | 🟡 中 | 服务端只校验格式并按原文存储；前端直接渲染该字符串，不做 Date 解析 |
| 评语与私人备注在弹窗或详情页混淆，管理员误把私密内容写进公开评语 | 🟡 中 | 两字段在弹窗分列并各自带可见性说明；详情页两个区块标签与色调区分，未公开评语带标记 |
| 评语的时间与正文脱节，出现有日期无正文的记录 | 🟢 低 | 展示以正文非空为唯一条件；日期留空或正文留空都不渲染区块，不追加互斥校验 |

## 5. Phase 依赖关系

```
Phase 1 ──→ Phase 2 ──→ Phase 3 ──→ Phase 4 ──→ Phase 5
```

Phase 1 为契约基石；Phase 2、3 消费接口与录入能力；Phase 4 与 Phase 3 共用详情页文件，顺延执行以避免同文件冲突；Phase 5 统一验证、文档与归档。

## 6. Subagent 协同规划

| 阶段 | 上下文依赖 | 并行收益 | 执行主体 | 决策理由 |
|------|-----------|---------|----------|----------|
| Phase 1：数据与接口 | 强（跨迁移、存储、处理器与导出） | 无（串行依赖同一契约） | 主线 | 字段命名与可见性口径需在一处统一，拆分会重复读盘并对齐成本高于改动本身 |
| Phase 2：设置弹窗 | 中（依赖类型与弹窗既有结构） | 低（单文件集中的表单改动） | 主线 | 改动小且需与 Phase 1 字段逐项对齐，委托的上下文重载成本大于收益 |
| Phase 3：详情页展示 | 中（依赖详情响应与既有排版） | 低（单区块与样式） | 主线 | 视觉需与瑞士排版一致，主线直接处理避免两轮返工 |
| Phase 4：审阅残留 | 强（跨接口、组件与样式，且复用 Phase 3 文件） | 低（四项互不相干但都很小） | 主线 | 每项都是单文件差分，委托的启动与验收成本高于改动本身 |
| Phase 5：验证与文档 | 中（依赖前四阶段结果） | 低（验收须串行） | 主线 | 测试与浏览器验收依附同一运行环境，无法与实现并行 |

> **协同结论**：本轮是围绕单一字段契约与四处小修正的窄链路改动，约 12 个文件、无独立可并行的自包含子任务；全部由主线执行，不派发 subagent。
