## 1. 背景与目标

用户反馈：明细页固定为原生分数，未遵循显示设置中的百分比模式。

Explore 阶段逐处读回只读得分面的取值渲染，确认「未遵循」的落点只有一个，并与详情、对比形成对照：

| 界面 | 取值渲染 | 是否遵循百分比模式 |
|------|----------|--------------------|
| 榜单维度列 / 组列 | `DimensionScore` | 是（11-12-v7 收口） |
| 模型详情 | `DimensionScore` | 是 |
| 对比表 / 移动卡片 | `DimensionScore` | 是 |
| 榜单明细抽屉（列头小箭头） | `formatDimension(row.scores[id])` | 否，固定一位小数原生分 |
| 工作台、评分弹窗 | `formatDimension` | 否，设计取舍：录入面始终显示实际分值 |
| 导出图片 | `formatDimension` | 否，设计取舍：导出不受显示模式影响 |

抽屉的取值与相对条都只吃原生分，`barWidth(value, max)` 恒按最高分归一，在「分差百分比」口径下与同列榜单取值框所表达的口径不一致。

目标：明细抽屉的取值与相对条接入与榜单 / 详情 / 对比同一套显示口径——百分比模式下显示百分比（相对强度或最高分占比）与色阶，实际分值模式下显示一位小数原生分；同一模型在抽屉与该列榜单单元格中逐字一致。

不在范围内：工作台、评分弹窗与导出图片的「始终实际分值」取舍，三处为录入面与导出面，本轮不改。

## 2. 阶段划分

### Phase 1：抽屉取值接入共享显示口径

| 项目 | 内容 |
|------|------|
| **输入** | `web/src/components/DetailDrawer.tsx` 的得分列渲染、`DimensionScore` 共享取值元素、`dimensionScoreRanges` 纯函数 |
| **输出** | 抽屉得分列改用 `DimensionScore`；Skip 单元格沿用同款取值框；色阶范围取该列全部可见模型（不计跳过行）的 min/max |
| **验收标准** | 百分比模式下抽屉取值与同列榜单取值框逐字一致（含 `%`）且带 `_tone_` 类；实际分值模式下同为一位小数；Skip 数字右缘与同列数值右缘对齐 |

### Phase 2：相对条口径共享

| 项目 | 内容 |
|------|------|
| **输入** | `web/src/lib/scoreEmphasis.ts`、`web/src/pages/ModelDetail.tsx` 中内联的模式三元表达式、抽屉的相对条 |
| **输出** | `scoreEmphasis.ts` 新增相对条填充纯函数（分差模式取相对强度，其余按最高分归一）；详情页与抽屉共用；抽屉相对条不再恒按最高分归一 |
| **验收标准** | 分差百分比模式下抽屉相对条宽度等于该值相对强度；最高分占比与实际分值模式下等于 `值 / 最高分`；详情页相对条宽度与改动前同值 |

### Phase 3：测试、文档与归档

| 项目 | 内容 |
|------|------|
| **输入** | Phase 1 与 Phase 2 的改动 |
| **输出** | 单测覆盖新纯函数；自动化基线结论；浏览器三态（分差百分比 / 最高分占比 / 关闭）验收结论；与代码一致的 Project.md；归档与提交 |
| **验收标准** | 验证基线全绿；浏览器读回抽屉与榜单逐字一致、相对条同口径；Project.md 与实际一致；Plan/Tasks 归入 `.docs/11-12-v8/` |

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 抽屉取值元素 | 复用 `DimensionScore` | 它是「只读得分」的唯一取值元素，百分比、色阶、小数位与取值框一次性对齐 | 在抽屉内联 `formatDisplayScore` 并另写取值样式：形成第二份口径与第二套取值框 |
| 取值色阶范围 | `dimensionScoreRanges(rows, [id])`，与榜单同一 helper 与同一行集合 | 抽屉是该列的另一视图，取色必须与列内一致 | 抽屉内自行计算 min/max：第三份范围实现 |
| Skip 单元格 | 沿用取值框（`DimensionScore.module.css` 的 `.score` 内嵌 `Skip`） | 取值框右内边距 9px，裸文字 Skip 会比同列数值右移 9px | 保留裸文字：与同列数值右缘错位 |
| 相对条口径 | 提取为 `scoreEmphasis.ts` 的纯函数，详情页与抽屉共用 | 该口径目前内联在详情页，抽屉再抄一遍即成两份漂移来源 | 抽屉内再写一次三元表达式：口径漂移风险 |
| 抽屉数值列宽 | 不改（74px） | 取值框宽度 58–63px 落在列内，右缘贴齐单元格右缘 | 放宽列宽：改动抽屉网格，收益为零 |
| 明细页判定 | 以榜单列头小箭头的明细抽屉为改动对象 | 详情页与对比页已走 `DimensionScore`（Explore 已读回代码），唯一固定原生分的只读面是抽屉 | 改详情页：无需改动，改后无差分 |

## 4. 风险清单

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 取值框纵向内边距抬高抽屉行高 | 🟢 低 | 行高由身份块（名 14px + 厂商 10px）决定，取值框 25px 不参与行高；浏览器读回行高与改动前一致 |
| 数值超大（原生分 > 1000）时取值框超出 74px 列宽 | 🟢 低 | 列宽与改动前同值，原生分超宽在改动前同样发生；不为此增加防御分支 |
| 详情页改用共享函数后相对条变化 | 🟢 低 | 表达式等价，浏览器读回相对条宽度与改动前同值 |
| 抽屉色阶与榜单色阶开关不一致 | 🟢 低 | 两处读同一 `dimensionScoreEmphasis` 偏好，同一开关同时生效 |

## 6. Subagent 协同规划

对照三维效益模型（任务复杂度、上下文关联度、经济与时间效益）评估本轮委托需求：

| 阶段 | 上下文依赖 | 并行收益 | 执行主体 | 决策理由 |
|------|-----------|---------|----------|----------|
| Phase 1：抽屉取值口径 | 强（依赖本轮对只读得分面的判定与共享取值元素约定） | 无 | 主线 | 单文件小差分，隔离会话重载上下文的开销高于改动本身 |
